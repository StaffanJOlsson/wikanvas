## Deviations and choices

Nothing frozen changed. Every new function and the `ItemRow` helpers are additive (R3).

- **D1. No schema change.** `0001-init/up.sql` is still the §5 DDL byte for byte; the existing indexes cover the W1
  queries. Other workstreams' DDL requests are for the merge stage.
- **D2. New dependency `unicode-normalization` 0.1.25** (MIT OR Apache-2.0) in `wikanvas-core`, for `slugify`'s NFKD. It
  was already in `Cargo.lock` (comrak → caseless). It is a plain version in the crate's `Cargo.toml`, because the root
  `[workspace.dependencies]` is not W1's (request W7-1).
- **D3. A deleted collection exists only in Trash.**
  - `GET`, `PATCH`, `move`, `DELETE`, `…/tree` and `…/updated` answer 404 for it.
  - `restore` of a live collection, or `purge` of one, is 409 `conflict`.
  - Its `item_count` is the number of items its deletion trashed (what a restore brings back).
- **D4. Restore and unarchive act on the unit.** They clear the item's trash or archive root, which may be an
  ancestor, and return that root as `RestoredItem`.
  - Restore of a live item, or unarchive of an unarchived one: 409 `conflict`.
  - Unarchive of a trashed item: 409 `read_only`.
  - Restore while the collection is deleted: 409 `parent_invalid` (§7.2).
- **D5. Soft-state rules where §5 is silent** (all in `wikanvas_core::tree`, mirrored by the store):
  - Trashing an archived item is allowed; it keeps its archive state. Trashing a trashed one is 409 `read_only`.
    When such an item is restored to the top level, its part of the archive unit becomes a unit of its own (D22).
  - Archive skips trashed descendants.
  - "The parent is gone" means purged, trashed, or archived while the root comes back unarchived.
  - Publish and unpublish of a trashed or archived item are 409 `read_only`. "Unpublish always allowed" means it has no
    publication preconditions (children, parent, already a draft).
- **D6. Purge.** `DELETE /trash/items/{id}` takes any trashed item (not only roots) with its subtree; a live one is 409
  `conflict`. `DELETE /trash` purges every item root and deleted collection.
- **D7. `discard_empty`:** a title counts as empty when it is blank after trimming; "no children" counts child rows in
  any state.
- **D8. `meta_version`** goes up on every change to the item row except a content save: title, `full_width`, move (the
  root and, across collections, its descendants), publication, archive, trash and their reverses, and collection
  delete and restore. `updated_at` / `updated_by` change on rename, `full_width`, move (the root) and publication; not on
  archive, trash, restore or a rebalance.
- **D9. `tree_version`** goes up on every create, move, rename, `full_width` change (it sets `updated_at`, which the
  tree shows and the `updated` order sorts by), publication change, archive, unarchive, trash, restore, discard,
  duplicate and rebalance, on any collection edit or reorder (the tree response holds the collection), on a collection
  rebalance for every collection whose `sort_key` it rewrites, and on collection delete and restore. `touch_content`
  bumps it only when the collection sorts by `updated`. Under the other orders a 304 tree may show an older
  `updated_at` / `content_at` (not structural, ARCHITECTURE D21).
- **D10. Tree order.** Parents come before children, depth first. Siblings go by `child_order`:
  - `manual`: by `sort_key`;
  - `title`: case-insensitive;
  - `updated` and `created`: newest first.
  The id breaks ties. `…/children` uses the same order; an archived item's children are its archived children.
- **D11. Lists.**
  - Every list but `/archive` leaves archived items out; `/archive` lists archive roots that are not trashed.
  - Stars (sidebar and `/starred`, in star order) show visible, unarchived items.
  - Starring a trashed item is 409 `read_only`; unstarring is idempotent.
  - `PUT …/star` without a position keeps an existing star's place.
  - `/trash` lists every item root, also those in a deleted collection (trashed before it), newest first.
- **D12. Cursor binding:** the list's name plus its parameters (`collection_id` for a collection's `updated`; for
  search the trimmed `q`, every filter and `sort`). The viewer is not part of it in M1.
- **D13. Search details.**
  - Only a bare last word becomes a prefix (`*`), never a user's phrase.
  - Terms without a letter or digit are dropped (FTS5 would make empty phrases of them).
  - Snippets come from the body (24 tokens, `…`); `score` is `-bm25`, so higher is better.
  - `/search/titles` uses the FTS column filter `title : (…)`; a blank `q` lists the recently updated items.
- **D14. Duplicate:** the copy goes right after the original and its title gets " (copy)" (an empty title stays empty);
  `full_width` is copied. The source must be live and unarchived (409 `read_only`).
- **D15. Optional bodies:** `POST …/publish` and `PUT …/star` accept an empty body (the defaults). A non-empty body must
  be `application/json` (415).
- **D16. `PATCH /items/{id}`** also answers with the new `ETag: "m{n}"`. An `If-Match` that is not `*` or `"m{n}"` never
  matches (412).
- **D17. `ItemDetail.board`:** `board_state.meta` plus `board_previews`. `svg_len` is that page's stored preview (any
  rev), and `preview_rev` the oldest rev among the stored previews (`null` when there are none). W6 may refine this.
- **D18.** The tree answers `Cache-Control: no-cache`. `GET /collections/{id}` answers 404 for anything that is
  neither a UUID nor a url_id.
- **D19. `POST /items`:** the dark board background follows `users.theme = 'dark'`, read with plain SQL in
  `routes/items.rs` (like W0b's D24) until W2's `users` module exists.
- **D20. Revision prune:** buckets are fixed UTC hours, days and weeks, and the newest revision in each bucket stays.
  The tiers by age are: under 24 h all, under 7 d hourly, under 90 d daily, then weekly. `manual` revisions are never
  pruned.
- **D21. OpenAPI:** the tags are `collections`, `items`, `tree`, `lists` and `search`. The generic pages appear as
  `Page_ListedItem` and `Page_SearchHit`.
- **D22. Archive units stay below their root** (review finding 1). Every trash or archive root is the row itself or
  an ancestor, with every row between them in the same unit; `Model::check_invariants` checks it. The one operation
  that could break it is a restore that moves a root which is still archived as part of an ancestor's unit (D5) to the
  top level. That root then becomes the archive root of the rows of its subtree that shared the old unit (one
  `UPDATE … WHERE archive_root_id = :old AND id IN subtree(:root)`, which also bumps their `meta_version`). It shows in
  `/archive`, unarchives by itself, and survives a purge of the old root, which takes only what is still below it.
  ARCHITECTURE §5 does not cover this case; the alternative (refusing to trash an archived non-root) would have
  changed D5.
- **D23. `MoveItem.parent_id` is required** (review finding 5), as §7.2 and the generated TS type already said:
  `#[serde(with = "required_option")]` + `#[schema(required = true)]`. A body without it is 422 `validation` with
  `details.field = "body"` (W2's envelope rule for every body that does not deserialize, like a `NewItem` without
  `collection_id`); the message names `parent_id`. `null` still means the top level. The Rust type is unchanged
  (`Option<Uuid>`), and serializing always writes the key, so Rust clients (the CLI) are unaffected. This makes the
  server stricter than W0b's DTO, which accepted an omitted key as `null`; it is recorded here as the contract fix,
  not a new contract. `common::required_option` is an additive helper (R3).
