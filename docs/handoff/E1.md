### How the engine side works (`embed_cards.rs`)

- **State.** `HostMode` gains one field, `cards: EmbedState` (the editing id, the title map, the revision the titles were
  applied at, the last reported layout, the force flag, the board's items with their revision, the last frame's focus,
  the frame whose press is swallowed, the frame number and the card opened in it, the zoom factor, the camera drawn).
  `HostMode::new(read_only, dark, events)` builds it (embed.rs and the tests use it).
- **Frame start** (`embed_frame_start`, right after `host_guard`, before shortcuts, chrome and canvas): a primary press
  while editing ends it with `press` and marks the frame as swallowing its canvas press; otherwise focus going false → true
  ends it with `focus`; the titles are applied when the revision changed.
- **Canvas.** `canvas_pointer` treats the swallowed frame's press as no press; `canvas()` records the camera it draws with.
- **Frame end** (`embed_frame_end`, at the end of `host_frame`): `gone` when the editing card is no longer a visible card of
  the current page; the titles again if the frame changed the revision (and a repaint then); then the layout, unless egui
  will discard the pass, reported when forced, first, or `worth_reporting` (cards, items, editing or page changed; camera,
  canvas or occluders changed while the page has or had a card; floats compared rounded to 1/1000).
- **Open.** `start_editing` delegates to the new `start_editing_at(id, cell, point)`, which first calls `open_embed`: for a
  card of a hosted board it sends `embed_open` (the double-click point times the zoom factor, `None` for Enter and the menu)
  and returns; in a read-only host it does nothing. Only `handle_double_click` passes a point.
- **Host calls** (`set_embed_editing`, `insert_embed`, `set_embed_titles`, `request_embed_layout`) are compiled for
  `test` and for wasm + `embed` only, like `host_snapshot`/`host_load`/`host_load_doc`, which are now also compiled for
  native tests (`cfg(any(test, all(target_arch = "wasm32", feature = "embed")))`).

## Deviations and decisions (for §18.14)

1. **One module instead of edits spread over `app.rs`.** The card logic lives in the new `inkboard-app/src/embed_cards.rs`
   (compiled on every target, so the native tests reach it), with its tests in `src/tests_embed.rs`; `app.rs` holds only
   the `HostEvents` methods, the `cards` field, `HostMode::new` and three calls; `tools.rs` and `rich_edit.rs` hold the
   hooks. The §18.3 table's per-file split is otherwise as specified. `HostMode`'s five new fields are one `EmbedState`.
2. **`start_editing_at(id, cell, point)`** carries the double-click point (§18.3 "hands its point to `start_editing`");
   `start_editing(id, cell)` keeps its signature and delegates with no point, so the other callers are untouched.
3. **egui's second pass.** egui 0.33 may run `App::update` twice for one frame (`request_discard`), which the spec did not
   cover. The layout is not reported from a pass that `will_discard()`; the swallowed press is keyed by
   `cumulative_frame_nr`, so it is swallowed in both passes; `embed_open` is sent once per frame and card.
4. **`gone` also when the card's layer is hidden**, not only when it leaves the page: the engine's `editing` then always
   names a card that the layout holds (the host ends editing for such a layout anyway, §18.5 step 5).
5. **No rotation handle only when hosted.** A card without a host page is a plain rectangle (as for its label, §18.3), so
   upstream Inkboard and the desktop app keep the handle.
6. **Titles.** `setEmbedTitles` applies the map at once (so a `snapshot()` right after holds it), then again on every
   revision change, at frame start and at frame end. The new label keeps the first span's style; a label with no span gets
   the card's title style (bold, `#1d2430`) instead of `set_plain`'s default style, so an API-written card with an empty
   label still looks like a card. An empty title gives an empty label (the host always sends `"Untitled"`).
7. **Numbers.** `zoom`, `originX/Y`, `canvas` and `occluders` are egui's `f32` camera and rects (what is drawn) times the
   zoom factor, as JS numbers (e.g. `1.0740000009536743`); card frames are the model's `f64` world units.
8. **Occluders** are sorted (top, left, bottom, right) and deduplicated, because egui's visible layer set is a hash set,
   and taken from `visible_layer_ids()` (this frame's and the last frame's), so a popup that just closed may stay an
   occluder for one more frame (the 500 ms repaint or the next input clears it).
9. **`insertEmbed` arguments.** A non-string `item`, or an `at` that is neither `'center'` nor a finite `{x, y}`, throws a
   `TypeError`; a `w` or `h` that is missing, not finite or not positive takes the default (480, 360) on its own.
   `insertEmbed` while the host edits a card leaves that editing as it is (the host decides).
10. **frame.js and the `gone` of a board switch.** The engine reports through microtasks, after the call that caused the
    event, by which time `current` is the new board. `frame.js` therefore remembers the board a `setBoard` leaves
    (`leaving`) and stamps the next `onEmbedEditEnd {reason: 'gone'}` with it; the next layout clears it. The frame test
    checks `{itemId: 'item-a', reason: 'gone'}` after `open()` of `item-b`.
11. **frame.js drag and drop.** For a drag with the type, `dragenter`/`dragover` always `stopPropagation()` (eframe's own
    canvas `dragover` calls `preventDefault()` on anything, which would accept the drop on a read-only board) and
    `preventDefault()` only when a writable board is open and the engine has not stopped; a `drop` with the type is always
    prevented and stopped (it never reaches eframe or the browser) and gives `onDropItem` only in that case. The
    `DraggedItem` is rebuilt from its four fields, so extra fields never reach the host.
12. **Frame-test readings.**
    - "One `onEmbedLayout` after `open()`": the engine sends two, the forced first frame's (the floating cards not yet
      sized by egui, at wrong places) and the settled one a frame later; the test waits until the reports settle and
      checks the last, and that at least one came.
    - "the context menu's Edit text": the test has a positive control on a writable board (the same right-click and row
      give `onEmbedOpen` with `point: null`) before the read-only run, so the row is known to be "Edit text"; the menu is
      found as the new occluder whose left edge is at the click (egui moves it up to fit the window).
    - The rotation test uses a variant of the fixture (a card left, the plain box right) so both handle points are clear
      of the floating cards; every test checks its points against the layout's occluders.
    - "the tool changes": after a click on the toolbar's Hand button (located from the tools card's occluder) the next
      drag pans, so `originX` changes.
