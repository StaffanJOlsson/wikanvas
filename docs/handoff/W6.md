## Deviations and choices

D1–D19 and W6-D20 onward are this note's items. "ARCHITECTURE Dn" names a decision of `docs/ARCHITECTURE.md`, as
do D31, D33, D45, D47, D51 and D53 in the older items.

Core and store:
- **D1. Signatures in §6.2 made fallible or named** (additive, R3):
  - `split(&str) -> Result<Split, BoardError>`, with `Split.assets: Vec<SplitAsset{id, mime, bytes}>`;
  - `splice(..) -> Result<String, BoardError>`;
  - `inspect(..) -> Result<Inspect{text, meta}, BoardError>`;
  - `preview(full, page) -> Result<Option<String>, BoardError>`, where a missing page is `None`;
  - new: `previews(full)`, which stops when the board's preview budget is spent (so it can have fewer entries than
    the board has pages, W6-D20); `Previewer`, `card_svg`, `PAGE_SVG_MAX`, `BOARD_SVG_MAX`, `TOO_LARGE`.
  - `Meta`/`MetaPage` moved to quire-core and are re-exported as `quire_store::boards::{Meta, MetaPage}`, with the
    same fields and JSON.
- **D2.** `split` drops a leading BOM, as `from_json` does, so the stored and returned bodies have none. Otherwise
  it re-emits every byte. `document.name` stays as sent in the stored body (GET replaces it), so the no-op test
  also compares the sent name. `splice` inserts a `name` when the document has none.
- **D3. Text and excerpt.** The text is one entry per line: the page name, then per object the box label, the
  connector label, table rows (cells separated by `\t`) and image LaTeX; empty entries are skipped. `text_excerpt`
  is the first 4096 bytes, cut at a char boundary (§9.5 "the first 4 KB"). W0b kept 200 characters; its unused
  `EXCERPT_CHARS` became `EXCERPT_BYTES`.
- **D4.** An asset sent with `data: ""` keeps the blob the board already had under that id. Without one it gets no
  `board_assets` row, and GET returns `""`.
- **D5.** As §6.2 orders it, the no-op test comes before If-Match: resending the stored body with a stale tag
  answers 200 with the current rev. If-Match is a tag list; `W/` is ignored, and tags that name no board revision
  (`"d3"`) never match.
- **D6.** A side effect of D53: when a session save has just written the `auto` revision of the current rev, the
  newest revision holds the current state, so the next token PUT writes no `pre-api` revision. The required test
  `token_put_writes_pre_api_revision` therefore makes two session saves first. It then checks one `pre-api` revision
  for the token, none for the same token's next PUT, and one more after another session write.

Server:
- **D7. PUT order.**
  - Checks before the body is read: If-Match (428) → `Content-Type: application/json` (415) → `X-Quire-Engine`
    (1–128 printable ASCII, else 422 `field: "X-Quire-Engine"`) → Content-Length against the limit (413) → item
    checks (404; 422 `field: "kind"` for a document; 409 `read_only`).
  - Then, under the permit: take the `board_work` permit → read the body with the limit and a 120 s deadline (408) →
    in `spawn_blocking`: UTF-8 (422 `invalid_board`), the JSON depth (422 `invalid_board`, W6-D26) and `prepare` (507
    below the free-space floor) → `save` in the writer.
  - The permit is taken before the body is read, so only one board body is in memory at a time (ARCHITECTURE D25).
    The cost: a slow upload delays board GETs and previews, bounded by the 30 s timeout layer.
- **D8.** The board limit is `QUIRE_MAX_BOARD_MB` × 1 MiB, like the other body limits; `details.limit_bytes`
  carries it. Board PUTs read the raw `Body`, so the 1 MiB default limit does not apply (tested).
- **D9. GET.** `Cache-Control: no-store` (§11 `/api` JSON), and never 304 (W6-D24). A document's or unknown id's board
  is 404.
- **D10. Download name.** `<title>.inkboard` under the §8 filename rule (control characters, `"`, `\` and `/`
  dropped; at most 200 characters; `board` when empty; an ASCII fallback with `_`; `filename*` percent-encoded UTF-8).
  §7.2 names no file name.
- **D11. The page route.**
  - `n` must be a `u32` inside the page count, else 404.
  - Another `rev` gives a 307 to the relative `/api/v1/items/{id}/board/pages/{n}?rev={cur}`, with `no-store`.
  - Every answer carries `ETag: "r{rev}"`, the CSP and `nosniff`, and gets 304 for a matching `If-None-Match`.
  - The handler itself gzips the SVG (`Vary: Accept-Encoding`) when the client accepts gzip.
  - A missing preview renders the board on demand (W6-D20), stores it, and serves page `n`. A render that waited for
    the permit first looks for a render of the same revision made meanwhile and serves that.
  - A page the budget left out (no row at a rendered revision) is served as the `card_svg` "Too large to preview"
    on the board's background, with the usual headers.
- **D12.** `BoardMeta.preview_rev` is the newest rev among the stored page previews; `svg_len` is each page's
  length at that rev, or `null` (also for a page the budget left out).
- **D13. The worker.** It renders an item 5 s after its last enqueue and at most 30 s after its first (§12 says
  "debounced by 5 s"; the cap keeps steady saving from starving it). It keeps only `db`, `blobs` and the permit, not
  `AppState`. A board counts as current when its page 0 has a row at the current rev (`previews::rendered`).

Web:
- **D14. `BoardFrameContext` additions** (additive): `progress`, `updateAvailable`, `savedAt`, `open`, `release`,
  `show`, `reload` and `requestFullscreen`. The store is zustand.
- **D15. When the iframe exists.**
  - It is created when a board page wants the editor (a BoardSurface attached): that is the first board visit, except
    for the no-engine and phone fallbacks.
  - It is visible only once the current board is open, so BoardLoading shows underneath while the engine loads.
  - `setActive` follows the board route.
- **D16.** The real driver connects on `load`. A page without `window.quireBoardFrame` rejects with
  `{kind:'download', missing:true}`. The host then GETs `frame.html` (no-store) and, on 404, refetches `/config`; the
  banner appears when `version` or `inkboard.base` changed.
- **D17. The unsaved snapshot.**
  - It lives in idb-keyval's default store under `quire.board.unsaved/<itemId>`.
  - A snapshot counts as "newer" when it was written after the item's `content_at` (else `updated_at`).
  - Restore opens the snapshot and PUTs it on its `baseRev`; a stale base shows the ConflictBanner.
  - HH:MM uses a 24-hour clock.
- **D18. "Keep mine as a copy".** It creates a sibling titled `<title> (copy)`, PUTs the snapshot at `"r1"`, and
  navigates to the copy; the original is not written. Network back-off is 1, 2, 5, 10, then 30 s, as in the doc
  session, with a retry at once on `online`.
- **D19. Exports.** SVG downloads `…/board/pages/0` without a `rev` (the current page 0); `.inkboard` downloads
  `…/board.inkboard`. Both flush pending saves first. The Nested popover uses `GET /items/{id}/children` under
  `['children', id]`, and its "+ Add a page" creates a child document.

After the review (see "Review findings"):
- **W6-D20. Preview budgets** (§12 says "renders every page SVG"; ARCHITECTURE D25 needs a bound).
  - `Previewer` estimates each page from the model before it renders: numbers at their printed width (`{:.2}` of the
    largest magnitude on the page), text from its layout (lines and runs, `&quot;` at six bytes), pens and connectors
    per point, and each image at the base64 size of its asset, once per image object. An image object costs the
    placeholder in the drawing, and its asset's base64 on top.
  - Per page at most `PAGE_SVG_MAX` (16 MiB); per board at most `BOARD_SVG_MAX` (48 MiB), counted with the real
    lengths. When a page does not fit what is left, the assets with the largest share are drawn as a grey placeholder
    SVG, largest first. When the drawing without images does not fit, the page is `card_svg` ("Too large to preview",
    under 1 KB). Within the budgets a preview is exactly `export_approx` (tested).
  - Pages are rendered one at a time and deflated in `spawn_blocking`; the deflated pages (bounded by the budget) are
    stored in one writer transaction, so one revision's rows stay together. Once the budget is spent the remaining
    pages get no row: `previews::state`/`get` report them as `Omitted` (there is a page-0 row at that rev), and the
    route serves the card. No schema change.
- **W6-D21. Owned `board_work` permits.** PUT, GET/download and renders take `acquire_owned()` and move the permit into
  each `spawn_blocking` and `Db::read`/`write` closure, so it is held until the blocking work ends even when the
  request is dropped (the 30 s timeout layer, a client that goes away).
- **W6-D22. The body budget** (ARCHITECTURE D25: "response buffers" share the headroom).
  - A process-wide weighted semaphore of `BODY_BUDGET_MIB` = 96 MiB (a `static` in `routes/boards.rs`, because
    `AppState` is W2's) covers response bodies of 1 MiB or more: the envelope GET, the `.inkboard` download and page
    SVGs. A body takes its size in MiB (a larger one takes all 96) before it is built: the GETs size it with
    `boards::envelope_len`, a stored page with its `svg_len`, an on-demand render with `PAGE_SVG_MAX`.
  - Order: the body budget is always taken before `board_work`, never while holding it. ARCHITECTURE D25 says no
    code path acquires a permit while holding one; this is the one exception, and the fixed order keeps it
    deadlock-free (PUTs and the worker take only `board_work`).
  - Such a body is sent with its `Content-Length` by a task that owns the bytes and the share: 256 KiB chunks through
    a 4-chunk channel. A client that reads nothing for 30 s (`SEND_STALL`), or is not done after 600 s
    (`SEND_DEADLINE`), loses the body: the task frees the bytes and the share, and the body ends with an error, so
    the connection is closed instead of sending a short body that looks complete.
- **W6-D23.** A large body that waits more than 10 s (`BODY_WAIT`) for its share answers 429 `rate_limited` with
  `reason: "busy"` and `Retry-After: 5` (the export pattern of D47); the CLI retries it.
- **W6-D24. The board GET never answers 304.** §7.2 lists `If-None-Match` for it, but its body holds the live title
  (`document.name`, ARCHITECTURE D31), which `"r{rev}"` does not version; D45 excludes such bodies from 304 (as the
  Markdown GET). The ETag stays for `If-Match`. The page route keeps its 304: the SVG holds no title.
- **W6-D25. The no-op test compares the asset bytes too.** §6.2 step 4 compares sha256(stripped) only, which has no
  asset bytes. A save is a no-op only when, in addition, every asset sent with data has the same sha256 as the
  board's `board_assets` row for that id, and that blob file exists. So new bytes under an old id, data sent for an
  asset stored without any (D4), and a lost blob file sent again are saved (rev + 1; `BlobStore::commit` restores the
  file).
- **W6-D26. JSON depth.** The PUT body is pre-scanned without recursion; more than `config::JSON_DEPTH` (100) levels is
  422 `invalid_board` ("nests JSON N levels deep"). §7.1 names the limit but not the code; boards use their own.
- **W6-D27. Table shapes.** `inspect` and `Previewer::new` refuse a table without rows or columns, or whose cells are
  not rows × columns (422 `invalid_board`). `Table::cell` and the SVG export index such a table out of bounds: before,
  the PUT panicked in `spawn_blocking` (500). The engine and inkboard-session's limits never produce one.
- **W6-D28. Store additions** (additive, R3): `BoardState.background`, `boards::envelope_len`, and in `previews`:
  `PageSvg`, `store`, `rendered`, `state`/`PageState`, `Preview::Omitted`. `board_previews::render` now takes the
  page and returns only it (`Rendered{rev, page}`; W6-internal).
- **W6-D29.** The page route gzips on a blocking thread; the PUT's UTF-8 check and depth scan run in `spawn_blocking`
  with `prepare` (50 MB scans off the two async workers).
- **W6-D30. The frame layer's z-index is 1** (was 10): above the in-flow canvas, below W3's menus (10), the Nested
  popover (30) and dialogs, which hang over the canvas.
- **W6-D31. Open order** (§9.5 Open: "1. Flush the current board (await). 2. GET board"). `host.flushPrevious(session)`
  awaits the flush of the session the frame showed before; a page's session stays active until its last flush is
  done, so reopening a board while its PUT is still running waits for that PUT. BoardSurface calls it before its GET;
  `openBoard` calls it too.

**W8:**
- `board get` returns `ETag: "r{rev}"`. `board put` needs `If-Match`; `--force` sends `*`.
- `board preview` without `rev` gets the current page (`no-cache`), or 204 for an empty page. With a stale `rev` it
  gets a 307, which the CLI does not follow, so it should send no `rev`.
- The PUT answers 413 (`details.limit_bytes`), 422 (`invalid_board`/`board_too_new`), 412 (`details {rev, etag}`) and
  428.
- `board get` never gets a 304 (W6-D24). `board get` and `board preview` can get 429 `rate_limited` with
  `reason: "busy"` and `Retry-After` while other large boards are being sent (W6-D23).

## Follow-ups

- Preview SVGs still embed their images as base64 (up to 16 MiB a page, W6-D20). List views can use `svg_len`
  (over 2 MB → a placeholder, per the DTO comment).
- If a client trickles its body, the `board_work` permit is held while the body arrives (D7). Per-token byte limits
  (W2) bound this.
- The preview estimate is an upper bound for every object kind the tests cover (`estimate_bounds_the_export`), not a
  proof for every SVG feature; the real length is what counts against the board budget.
- Rendering time is not bounded the way memory is: Inkboard's `Page::connector_path` looks objects up linearly, so a
  page with many connectors renders in quadratic time under `board_work` (upstream, §15).
- Two readers of large boards at once can hold the whole body budget for up to 600 s each; a third large GET gets 429
  `busy` meanwhile (W6-D22, W6-D23). Small boards are not affected.
