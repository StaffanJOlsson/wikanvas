## Deviations and choices

Core and store:
- **D1. Signatures in §6.2 made fallible or named** (additive, R3):
  - `split(&str) -> Result<Split, BoardError>`, with `Split.assets: Vec<SplitAsset{id, mime, bytes}>`;
  - `splice(..) -> Result<String, BoardError>`;
  - `inspect(..) -> Result<Inspect{text, meta}, BoardError>`;
  - `preview(full, page) -> Result<Option<String>, BoardError>`, where a missing page is `None`;
  - new: `previews(full)`.
  - `Meta`/`MetaPage` moved to quire-core and are re-exported as `quire_store::boards::{Meta, MetaPage}`, with the
    same fields and JSON.
- **D2.** `split` drops a leading BOM, as `from_json` does, so the stored and returned bodies have none. Otherwise
  it re-emits every byte. `document.name` stays as sent in the stored body (GET replaces it), so the no-op test
  also compares the sent name. `splice` inserts a `name` when the document has none.
- **D3. Text and excerpt.** The text is one entry per line: the page name, then per object the box label, the
  connector label, table rows (cells separated by `\t`) and image LaTeX; empty entries are skipped. `text_excerpt`
  is the first 4096 bytes, cut at a char boundary (§9.5 "the first 4 KB"). W0b kept 200 characters; its unused
  `EXCERPT_CHARS` became `EXCERPT_BYTES`.
- **D4.** An asset sent with `data: ""` keeps the blob the board already had under that id. Without one it gets no
  `board_assets` row, and GET returns `""`.
- **D5.** As §6.2 orders it, the no-op test comes before If-Match: resending the stored body with a stale tag
  answers 200 with the current rev. If-Match is a tag list; `W/` is ignored, and tags that name no board revision
  (`"d3"`) never match.
- **D6.** A side effect of D53: when a session save has just written the `auto` revision of the current rev, the
  newest revision holds the current state, so the next token PUT writes no `pre-api` revision. The required test
  `token_put_writes_pre_api_revision` therefore makes two session saves first. It then checks one `pre-api` revision
  for the token, none for the same token's next PUT, and one more after another session write.

Server:
- **D7. PUT order.**
  - Checks before the body is read: If-Match (428) → `Content-Type: application/json` (415) → `X-Quire-Engine`
    (1–128 printable ASCII, else 422 `field: "X-Quire-Engine"`) → Content-Length against the limit (413) → item
    checks (404; 422 `field: "kind"` for a document; 409 `read_only`).
  - Then, under the permit: take the `board_work` permit → read the body with the limit and a 120 s deadline →
    UTF-8 (422 `invalid_board`) → `prepare` (507 below the free-space floor) in `spawn_blocking` → `save`.
  - The permit is taken before the body is read, so only one board body is in memory at a time (D25). The cost: a
    slow upload delays board GETs and previews, bounded by the 30 s timeout layer.
- **D8.** The board limit is `QUIRE_MAX_BOARD_MB` × 1 MiB, like the other body limits; `details.limit_bytes`
  carries it. Board PUTs read the raw `Body`, so the 1 MiB default limit does not apply (tested).
- **D9. GET.** `Cache-Control: no-store` (§11 `/api` JSON) and 304 for a matching `If-None-Match`. A document's or
  unknown id's board is 404.
- **D10. Download name.** `<title>.inkboard` under the §8 filename rule (control characters, `"`, `\` and `/`
  dropped; at most 200 characters; `board` when empty; an ASCII fallback with `_`; `filename*` percent-encoded UTF-8).
  §7.2 names no file name.
- **D11. The page route.**
  - `n` must be a `u32` inside the page count, else 404.
  - Another `rev` gives a 307 to the relative `/api/v1/items/{id}/board/pages/{n}?rev={cur}`, with `no-store`.
  - Every answer carries `ETag: "r{rev}"`, the CSP and `nosniff`, and gets 304 for a matching `If-None-Match`.
  - The handler itself gzips the SVG (`Vary: Accept-Encoding`) when the client accepts gzip.
  - A missing preview renders every page on demand, stores them, and serves page `n`.
- **D12.** `BoardMeta.preview_rev` is the newest rev among the stored page previews; `svg_len` is each page's
  length at that rev, or `null`.
- **D13. The worker.** It renders an item 5 s after its last enqueue and at most 30 s after its first (§12 says
  "debounced by 5 s"; the cap keeps steady saving from starving it). It keeps only `db`, `blobs` and the permit, not
  `AppState`.

Web:
- **D14. `BoardFrameContext` additions** (additive): `progress`, `updateAvailable`, `savedAt`, `open`, `release`,
  `show`, `reload` and `requestFullscreen`. The store is zustand.
- **D15. When the iframe exists.**
  - It is created when a board page wants the editor (a BoardSurface attached): that is the first board visit, except
    for the no-engine and phone fallbacks.
  - It is visible only once the current board is open, so BoardLoading shows underneath while the engine loads.
  - `setActive` follows the board route.
- **D16.** The real driver connects on `load`. A page without `window.quireBoardFrame` rejects with
  `{kind:'download', missing:true}`. The host then GETs `frame.html` (no-store) and, on 404, refetches `/config`; the
  banner appears when `version` or `inkboard.base` changed.
- **D17. The unsaved snapshot.**
  - It lives in idb-keyval's default store under `quire.board.unsaved/<itemId>`.
  - A snapshot counts as "newer" when it was written after the item's `content_at` (else `updated_at`).
  - Restore opens the snapshot and PUTs it on its `baseRev`; a stale base shows the ConflictBanner.
  - HH:MM uses a 24-hour clock.
- **D18. "Keep mine as a copy".** It creates a sibling titled `<title> (copy)`, PUTs the snapshot at `"r1"`, and
  navigates to the copy; the original is not written. Network back-off is 1, 2, 5, 10, then 30 s, as in the doc
  session, with a retry at once on `online`.
- **D19. Exports.** SVG downloads `…/board/pages/0` without a `rev` (the current page 0); `.inkboard` downloads
  `…/board.inkboard`. Both flush pending saves first. The Nested popover uses `GET /items/{id}/children` under
  `['children', id]`, and its "+ Add a page" creates a child document.

## Requests for the W1–W8 owners

**W1:**
1. Fill `ItemDetail.board` with `quire_store::boards::board_meta(conn, item_id)`, which adds `rev`, `preview_rev` and
   `svg_len` to the §5 meta. Do not read `board_state.meta` alone.
2. Duplicate keeps using `boards::copy` (it shares blobs and copies no previews).
3. The revision prune must keep the `assets` of inkboard revisions; they are blob GC roots.
4. The board page's Nested popover calls `GET /items/{id}/children`.

**W2:**
1. **Timeout.** §8 gives board PUTs a 120 s body deadline, but the global 30 s `TimeoutLayer` (`app.rs`) cuts them
   first. Exempt `PUT /api/v1/items/{id}/board` (and uploads) from it; the handler applies its own
   `routes::boards::BODY_DEADLINE`.
2. **Seed.** The seed's `boards::init_with` now splits inline assets into blobs, and the fixture is no longer empty: 7
   objects, with labels in `item_text`. A seed test that expects an empty board must change.
3. **Startup.** Call `inkboard_core::model::seed_ids(<random u64>)` at startup (§6.2), so server-made ids never
   repeat.
4. **Content-Disposition.** `routes::boards::content_disposition(title, ext)` follows §8 and could move into
   `headers.rs` for attachments (and W4's Markdown download).
5. **Compression.** A CompressionLayer for `/api` must skip responses that already carry `Content-Encoding`; the
   preview route gzips itself. tower-http's layer already skips them.
6. **Stub manifest.** Answer `inkboard: null` for a stub manifest (W0b request W2-3). The board page then shows
   "Whiteboard engine not installed" instead of creating an iframe.

**W3:**
1. Spread `useBoardWarmup()` (`web/src/board/warmup.ts`) on every sidebar board row. It provides the `onPointerEnter`
   and `onPointerLeave` of the 300 ms warm-up (§9.5).
2. `BoardFrameHost` now calls `useConfig()`. Keep the AppShell mount as it is.

**W5:**
1. The host relies on these frame behaviours:
   - `connect` rejects with `{kind, message}`;
   - engine-level failures send `onError{itemId: null}`;
   - `open()` resolves once the board is shown;
   - every event carries the current `itemId`.
2. `window.quireBoardFrame` must be set by the frame's module script before `load` (the stub already does this),
   because the driver reads it in the iframe's `load` handler.

**W7:**
1. §6.2: take the D1 signatures; §5/§9.5: `text_excerpt` holds 4 KB (D3).
2. Check the board host in a real browser with the real dist: rect tracking, the hidden/inert switch, fullscreen and
   double-Esc. The fake frame cannot cover these.
3. For `integration::board_blobs_freed_after_purge_and_gc`, `search_finds_board_label_over_http` and
   `board_token_put_then_text_and_preview`: the board routes and `quire_store::boards::*` are ready.
4. No borrowed code in W6, so nothing goes into THIRD_PARTY.md.

**W8:**
- `board get` returns `ETag: "r{rev}"`. `board put` needs `If-Match`; `--force` sends `*`.
- `board preview` without `rev` gets the current page (`no-cache`), or 204 for an empty page. With a stale `rev` it
  gets a 307, which the CLI does not follow, so it should send no `rev`.
- The PUT answers 413 (`details.limit_bytes`), 422 (`invalid_board`/`board_too_new`), 412 (`details {rev, etag}`) and
  428.

## Follow-ups

- Preview SVGs embed their images as base64, so one page can be large. List views can use `svg_len` (over 2 MB → a
  placeholder, per the DTO comment).
- If a client trickles its body, the `board_work` permit is held while the body arrives (D7). Per-token byte limits
  (W2) bound this.
