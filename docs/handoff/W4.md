## Deviations and choices

Contracts (R3, all additive):
- **D1. `DocSchema` refined** (W0b D15 called it a proposal): `top_node`, `NodeSpec.marks` (the allowed marks, null for the
  default), `MarkSpec.inclusive`, `AttrSpec.type` in TypeScript notation (`integer`, `string | null`,
  `integer[] | null`, `"info" | "tip" | …`). `fixtures/schema/v1.json` is exactly this JSON; the web dumper takes the
  attribute types from its `ATTR_TYPES` table and fails on an attribute it has no type for.
- **D2. Store API.** Added `save_update`, `get`, `prosemirror`, `markdown`, `write_content(db, ContentWrite, Author,
  now)` (`ContentWrite` carries the input, `IfMatch`, `merge`, `title_from_h1`, the credential, normalized query and
  body hash for the request hash, the public origin and the cap), `init_seed`, `etag`, `parse_etag`, `links`,
  `DbLookup`, `PmJson`, `SEED_WRITING_ID`/`SEED_BOARD_ID`. `is_empty` now takes `&Connection` (a `&Transaction` still
  works through deref, so W1's callers are unchanged). The `pre-api` recovery point runs inside `save_update`, so the
  Yjs POST and both PUTs get it the same way.
- **D3. `quire_core::convert::yrs`** re-exports yrs, so `quire-server`'s API tests speak Yjs without a manifest change.

Formats and conversion:
- **D4. Raw JSON mark order.** yrs reports a text chunk's attributes as a hash map, so `pm::raw` lists marks in schema
  rank order (unknown ones last). That is the order y-tiptap writes them in (one insert per text run, all marks,
  rank order), so every web fixture matches; Yjs would list a mark added to existing text later last.
- **D5. Map values and byte stability.** yrs encodes the keys of a map value (an item link's `{href, itemId}`) in hash-map
  order. A repeated PUT gives the same client id, clocks and content, and byte-identical updates unless it writes an
  item link. `write_server_fixtures` therefore rewrites a `.bin` only when its document or state vector changed, and
  its check compares content, so `git diff --exit-code fixtures/ydoc/server` holds. Everything else the writer emits
  is deterministic: text is inserted plain and formatted one mark key at a time in name order, attributes in name
  order, new `blockId`s from `sha256(h ‖ counter)` as UUID v4.
- **D6. The Y walk** (§6.1 leaves the details open): every paragraph, heading and code block is a line; a hard break ends
  a line; an image caption is a line; a table row is a line with `\t` between cells (a cell's lines joined by a space);
  other elements are containers; empty lines are dropped. Mentions contribute no text. `*.links.json` holds
  `{links: [{target_id, kind}], attachment_ids, is_empty}`, computed by the web writer independently of Rust.
- **D7. The Markdown block map.** `md_out::lower` applies the §6.4 lossy rules in JSON space and tags each node with the
  base child it stands for; `md_normalize` is the same without tags, and the printer renders the lowered tree, so
  `print = render ∘ lower`. At write time the lowered base is used when it equals the re-parse of the printed base;
  where it does not (a lossy step the lowering does not model, e.g. comrak autolinking an e-mail address in text),
  `convert::comparison_tree` keeps the re-parsed top-level blocks, each mapped to the lowered block it equals or
  standing for the base blocks of its gap. Unchanged Markdown is never touched either way.
- **D8. Markdown rules the table leaves open** (all in the goldens): a link outside the allow-list keeps only its text;
  `[@…](quire://item/<uuid>)` is a mention even when the item is unknown (it renders "Deleted item"), and
  `![…](quire://item/<uuid>)` of an unknown item a board embed (both with `unknown_item`), so a deleted target
  round-trips; a same-instance item URL keeps its `href` with the `itemId`, and prints as `quire://item/<id>`; an HTML
  block's lines are joined by hard breaks; a checkbox after the first item of a plain list stays text; an alert's
  custom title becomes a first paragraph; a list item that starts with a non-paragraph gets an empty first paragraph
  (TipTap's `paragraph block*`); bare URLs in text are escaped (`https\://`, `&#119;ww.`) so they do not autolink;
  `-`/`*` alternate after any bullet or task list, `.`/`)` after an ordered one; an empty item prints its marker
  alone; mentions and board embeds print the live title ("Deleted item" / "Board" when unknown).
- **D9. Tables in Markdown writes.** A changed table whose base has spans keeps them when the rows keep their shape and
  the expanded filler cells stay empty; otherwise it is replaced as a whole (`table_span_dropped`). Paired cells keep
  `colwidth` and `align`.
- **D10. Pairing details:** an empty base textblock pairs with any target block of its type (so a first write fills the
  empty paragraph the editor put into a new document instead of leaving it behind; a lowered document of only empty
  paragraphs keeps the first as its block). Myers gives up beyond 2000 edits at one level (then only the common
  prefix and suffix anchor), and similarity pairing looks 64 base children ahead.
- **D11a. JSON key order.** `oas3` (a quire-server dev-dependency) turns on serde_json's `preserve_order` by default,
  so in workspace test and clippy builds `serde_json::Map` keeps insertion order. The diff writer's content hash and
  the server fixture writer therefore serialize through `schema::canonical`/`schema::sorted` (sorted keys, explicit
  stack); nothing in W4 depends on the map type (request W2-3).
- **D11. Recursion bounds.** Y readers and JSON normalize/validate are iterative (Y walks refuse more than 5000 levels);
  the Markdown printer recurses up to 200 container levels and prints deeper content as the text of its blocks; the
  parser's block conversion recurses within the pre-scan's bound of 100, its inline conversion is iterative.
- **D12. Seed.** `getting-started.bin` is "Welcome to Quire"; it mentions "Writing in Quire"
  (`fixtures/ydoc/writing-in-quire.bin`) and embeds the example board through placeholder ids, which
  `docs::init_seed` replaces (request W2-1).

HTTP:
- **D13.** Document routes take UUIDs only (`IdPath`; §7.1 lets only `GET /items/{id}` and collections take url_ids). A
  board id is 422 `validation` (`field: "kind"`).
- **D14.** The Yjs POST limit (16 MiB) applies to the JSON body. A JSON body nested beyond serde_json's 128 levels is
  422 `invalid_document` at `/doc`. An `If-Match` that is no `"d{n}"` is stale (412). `schema_version` other than 1 in
  a ProseMirror PUT is 422 `validation`. The download name is the title's ASCII slug (other characters become `-`).
- **D15.** A stale strict PUT counts as "already equal" only when the title matches too under `?title=from_h1`.

Web:
- **D16.** StarterKit runs without TrailingNode (it would repair server-written documents on load, so
  `serverWritten.test.ts` could not hold) and without Typography; its Link is replaced by Quire's (`href`, `itemId`;
  `target`/`rel` only as render attributes), Mention's attrs are only `itemId`, Image's exactly §6.1. TipTap 3.32's
  table cells carry an `align` attr; it is part of schema v1 (Markdown drops it, as alignment).
- **D17.** Fixture mode: Y `clientID` 1, UniqueID ids `00000000-0000-4000-8000-<12 hex counter>`.
- **D18.** lowlight is a stand-in until its chunk loads; then each code block gets a no-op `setNodeMarkup` so the
  plugin redraws (no Y change).
- **D19.** The Contents column lists top-level headings only.
- **D20.** New-empty-item discard: the page discards an item it was told it created (`location.state.created`, which its
  own "Add a page" sets) or, until W3 passes that state, one created less than 2 minutes ago that is untitled and
  never edited (request W3-1). The server's `discard_empty` check is the real guard (409 `not_empty` is ignored).
- **D21.** Uploads use XMLHttpRequest for progress; a placeholder widget marks the position, and a failure shows Retry.

## Follow-ups

- The editor UI was exercised by the unit tests only (headless editors and component renders); no dev server ran. A
  look at the page in a browser (menus, block handle, popover placement) belongs in W7's end-to-end pass.
- Board embeds show the preview once W6 renders previews (`preview_rev`); until then the card shows an icon.
- A link mark with an item id could be written as `{href}` alone (the reader fills `itemId` from the schema default) to
  make every update byte-stable; it would change what the editor stores, so it is left for the owner.
