## Deviations and choices

Contracts (R3, all additive):
- **D1. `DocSchema` refined** (W0b D15 called it a proposal): `top_node`, `NodeSpec.marks` (the allowed marks, null for the
  default), `MarkSpec.inclusive`, `AttrSpec.type` in TypeScript notation (`integer`, `string | null`,
  `integer[] | null`, `"info" | "tip" | …`). `fixtures/schema/v1.json` is exactly this JSON; the web dumper takes the
  attribute types from its `ATTR_TYPES` table and fails on an attribute it has no type for.
- **D2. Store API.** Added `save_update`, `get`, `prosemirror`, `markdown`, `write_content(db, ContentWrite,
  by: &WriteBy, now)` (the PLAN W4 shape; `ContentWrite` carries the input, `IfMatch`, `merge`, `title_from_h1`, the
  credential, normalized query and body hash for the request hash, the public origin and the cap), `init_seed`,
  `etag`, `parse_etag`, `links`, `DbLookup`, `Author` (an owned `WriteBy`), `PmJson` (`Keep`, `Set(&Value)`,
  `Raw(&str)`: JSON text stored as sent, `Clear`), `SEED_WRITING_ID`/`SEED_BOARD_ID`. `is_empty` now takes `&Connection` (a `&Transaction` still
  works through deref, so W1's callers are unchanged). The `pre-api` recovery point runs inside `save_update`, so the
  Yjs POST and both PUTs get it the same way.
- **D3. `quire_core::convert::yrs`** re-exports yrs, so `quire-server`'s API tests speak Yjs without a manifest change.

Formats and conversion:
- **D4. Raw JSON mark order.** yrs reports a text chunk's attributes as a hash map, so `pm::raw` lists marks in schema
  rank order (unknown ones last). That is the order y-tiptap writes them in (one insert per text run, all marks,
  rank order), so every web fixture matches; Yjs would list a mark added to existing text later last.
- **D5. Map values and byte stability.** yrs encodes the keys of a map value (an item link's `{href, itemId}`) in hash-map
  order. A repeated PUT gives the same client id, clocks and content, and byte-identical updates unless it writes an
  item link. `write_server_fixtures` therefore rewrites a `.bin` only when its document or state vector changed, and
  its check compares content, so `git diff --exit-code fixtures/ydoc/server` holds. Everything else the writer emits
  is deterministic: text is inserted plain and formatted one mark key at a time in name order, attributes in name
  order, new `blockId`s from `sha256(h ‖ counter)` as UUID v4.
- **D6. The Y walk** (§6.1 leaves the details open): every paragraph, heading and code block is a line; a hard break ends
  a line; an image caption is a line; a table row is a line with `\t` between cells (a cell's lines joined by a space);
  other elements are containers; empty lines are dropped. Mentions contribute no text. `*.links.json` holds
  `{links: [{target_id, kind}], attachment_ids, is_empty}`, computed by the web writer independently of Rust.
- **D7. The Markdown block map.** `md_out::lower` applies the §6.4 lossy rules in JSON space and tags each node with the
  base child it stands for; `md_normalize` is the same without tags, and the printer renders the lowered tree, so
  `print = render ∘ lower`. At write time the lowered base is used when it equals the re-parse of the printed base;
  where it does not (a lossy step the lowering does not model, e.g. comrak autolinking an e-mail address in text),
  `convert::comparison_tree` keeps the re-parsed top-level blocks, each mapped to the lowered block it equals or
  standing for the base blocks of its gap. Unchanged Markdown is never touched either way.
- **D8. Markdown rules the table leaves open** (all in the goldens): a link outside the allow-list keeps only its text;
  `[@…](quire://item/<uuid>)` is a mention even when the item is unknown (it renders "Deleted item"), and
  `![…](quire://item/<uuid>)` of an unknown item a board embed (both with `unknown_item`), so a deleted target
  round-trips; a same-instance item URL keeps its `href` with the `itemId`, and prints as `quire://item/<id>`; an HTML
  block's lines are joined by hard breaks; a checkbox after the first item of a plain list stays text; an alert's
  custom title becomes a first paragraph; a list item that starts with a non-paragraph gets an empty first paragraph
  (TipTap's `paragraph block*`); bare URLs in text are escaped (`https\://`, `&#119;ww.`) so they do not autolink;
  `-`/`*` alternate after any bullet or task list, `.`/`)` after an ordered one; an empty item prints its marker
  alone; mentions and board embeds print the live title ("Deleted item" / "Board" when unknown).
- **D8a. Delimiters that must flank** (review finding 3). The printer writes inline content as cells and then runs
  `md_out::fix_runs`, a linear pass that mirrors comrak's flanking rules (CommonMark's, with `~` and `=` skipped when
  looking at a run's neighbours): a letter (or a non-ASCII character Rust cannot classify) next to a delimiter that
  would otherwise not open or close is written as a decimal character reference (`&#120;*\_y\_*`), whitespace at the
  inside edge of a mark that the lowering does not move (a no-break space) likewise, and text `=`/`_` that could open
  (or close an open) highlight or `_` emphasis is escaped. Bold and italic use `_`/`__` instead of `*`/`**` in two
  places: right after a `*` closer (so closers and openers never merge into one run, which the "multiple of 3" rule
  can leave unmatched), and when opened while the other is open from a `***` run (an opener that can also close
  would close that run). Italic inside a lone `**`, and the reverse, keep `*`: the rule of 3 protects them. An `@`
  with an e-mail local-part character before it and a domain character after it is escaped (`a\@b.co`; an escaped
  character is its own node while comrak looks for addresses, a character reference is not). A `!` before a mention
  is escaped as before a link. The output changes only for documents whose old output did not parse back; the
  goldens are unchanged.
- **D9. Tables in Markdown writes.** A changed table whose base has spans keeps them when the rows keep their shape and
  the expanded filler cells stay empty; otherwise it is replaced as a whole (`table_span_dropped`). Paired cells keep
  `colwidth` and `align`.
- **D10. Pairing details:** an empty base textblock pairs with any target block of its type (so a first write fills the
  empty paragraph the editor put into a new document instead of leaving it behind; a lowered document of only empty
  paragraphs keeps the first as its block). Myers gives up beyond 2000 edits at one level (then only the common
  prefix and suffix anchor), and similarity pairing looks 64 base children ahead.
- **D11a. JSON key order.** `oas3` (a quire-server dev-dependency) turns on serde_json's `preserve_order` by default,
  so in workspace test and clippy builds `serde_json::Map` keeps insertion order. The diff writer's content hash and
  the server fixture writer therefore serialize through `schema::canonical`/`schema::sorted` (sorted keys, explicit
  stack); nothing in W4 depends on the map type (request W2-3).
- **D11. Recursion bounds.** Y readers and JSON normalize/validate are iterative (Y walks refuse more than 5000 levels);
  the Markdown printer recurses up to 200 container levels and prints deeper content as the text of its blocks; the
  parser's block conversion recurses within the bound `md_in::check_depth` enforces (100 containers), its inline
  conversion is iterative.
- **D11b. The Markdown nesting limit** (review finding 1). §6.4 step 1 asks for a line pre-scan that refuses nesting
  deeper than 100 before comrak runs. A line scan cannot know comrak's container structure exactly (several markers
  per line, tabs, lazy continuation lines, CR endings, items continued under a narrower quote prefix), so it is two
  steps: `md_in::prescan` is a stateless per-line upper bound (`markers + whitespace columns / 2` of the line's
  container prefix, which bounds the depth of every line that opens a container; it only over-counts) and refuses
  above `PRESCAN_LIMIT` = 200 before comrak (twice 100, so lists indented by four columns per level still reach the
  exact check; the error position is where the bound passed 100); then `md_in::check_depth` refuses more than 100
  containers (quotes, alerts, list items) in comrak's tree, iteratively, at the `line:column` of the first too deep,
  before the conversion. comrak itself opens at most 100 containers per line. Request W7-4 updates the §6.4 text.
- **D12. Seed.** `getting-started.bin` is "Welcome to Quire"; it mentions "Writing in Quire"
  (`fixtures/ydoc/writing-in-quire.bin`) and embeds the example board through placeholder ids, which
  `docs::init_seed` replaces (request W2-1).

HTTP:
- **D13.** Document routes take UUIDs only (`IdPath`; §7.1 lets only `GET /items/{id}` and collections take url_ids). A
  board id is 422 `validation` (`field: "kind"`).
- **D14.** The Yjs POST limit (16 MiB) applies to the JSON body. A JSON body nested beyond serde_json's 128 levels is
  422 `invalid_document` at `/doc`. The Yjs POST reads `pm_json` as raw JSON text and stores it as sent; it must be a
  JSON object (422 `validation`, `field: "pm_json"`), and `null` is the same as absent (it used to store `"null"`).
  It is not checked against schema v1: it is the editor's cache and may hold a newer client's nodes.
- **D14a. Permits before the body** (review finding 2). A PUT takes its two `doc_work` permits, and a Yjs POST its
  one, after the header checks (415, 428) and before reading the body, and parses it (JSON, UTF-8, sha256, base64)
  in `spawn_blocking`. So a request waiting for a permit holds no body and no parse result, and the permits bound
  the memory of D25 again. Taking them after the read would let waiting requests each buffer up to 16 MiB; taking
  them before lets a slow sender hold them, but only for the 30 s request timeout (§7.1). A 413 now comes after the
  wait for permits. An `If-Match` that is no `"d{n}"` is stale (412). `schema_version` other than 1 in
  a ProseMirror PUT is 422 `validation`. The download name is the title's ASCII slug (other characters become `-`).
- **D15.** A stale strict PUT counts as "already equal" only when the title matches too under `?title=from_h1`.

Web:
- **D16.** StarterKit runs without TrailingNode (it would repair server-written documents on load, so
  `serverWritten.test.ts` could not hold) and without Typography; its Link is replaced by Quire's (`href`, `itemId`;
  `target`/`rel` only as render attributes), Mention's attrs are only `itemId`, Image's exactly §6.1. TipTap 3.32's
  table cells carry an `align` attr; it is part of schema v1 (Markdown drops it, as alignment).
- **D17.** Fixture mode: Y `clientID` 1, UniqueID ids `00000000-0000-4000-8000-<12 hex counter>`.
- **D18.** lowlight is a stand-in until its chunk loads; then each code block gets a no-op `setNodeMarkup` so the
  plugin redraws (no Y change).
- **D19.** The Contents column lists top-level headings only.
- **D20.** New-empty-item discard: the page discards only an item it was told it created (`location.state.created`,
  which its own "Add a page" sets; review finding 4 removed the "untitled, never edited, younger than 2 minutes"
  fallback, which could delete an item another client had just created). Items created from the top bar, the
  sidebar or the item menu are discarded once W3 passes that state (request W3-1). The server's `discard_empty`
  check stays the guard against deleting content (409 `not_empty` is ignored).
- **D21.** Uploads use XMLHttpRequest for progress; a placeholder widget marks the position, and a failure shows Retry.

## Review findings

All five findings of the independent review hold; none is rejected. Each was checked against the code and the docs,
and fixed inside W4's Owns table (the remaining wording and wiring are requests W3-1, W7-4, W7-5 and W7-6).

1. **High: the Markdown pre-scan undercounted nesting** (`convert/md_in.rs`). Confirmed: it pushed only the first
   list marker's content column per line, and it also missed tabs, lazy continuation lines, CR line endings and
   items continued under a narrower quote prefix, so the recursive block conversion could see about 1000 levels and
   overflow a worker's stack. Fixed (D11b): a stateless per-line upper bound before comrak (refused above 200), then
   the exact limit of 100 containers on comrak's tree, checked iteratively before the conversion. Tests:
   `convert::tests::markdown_depth_bounded_across_lines` (the review's input shape, tabs, quote prefixes, lazy lines,
   CR and CRLF, empty items; exactly 100 levels pass, also with four-column indentation),
   `markdown_prescan_rejects_depth_101` (updated: the 1 MiB `>` line is still refused before comrak at `1:101`), and
   `docs::markdown_put_nested_over_lines_422_and_server_survives` (the review's 10-line body is 422, and the server
   keeps serving).
2. **Medium: bodies were parsed before the `doc_work` permits** (`routes/docs.rs`). Confirmed for both PUTs and the
   Yjs POST. Fixed (D14a, D14): the permits are taken after the 415 and 428 checks and before the body is read; JSON,
   UTF-8, sha256 and base64 work runs in `spawn_blocking`; the Yjs POST keeps `pm_json` as raw JSON text (an object,
   or null for none), so its memory is about the body's size. Tests: `docs::doc_writes_parse_bodies_under_permits`
   (with every permit held, a malformed PUT and POST wait, then answer 422), `docs::yjs_post_pm_json_is_an_object`,
   and the store's `docs::api_write_clears_pm_json` (now also `PmJson::Raw`, stored as sent).
3. **Medium: the printer broke the round trip for delimiters touching words** (`convert/md_out.rs`). Confirmed both
   cases (`x*\_y\_*` lost the italic, `a@b.co` became a mailto link). Fixed (D8a): character references where a
   delimiter would not flank, `_` delimiters where `*` runs could merge or be matched with the wrong opener, escaped
   text `=`/`_` that could pair, and an escaped `@` in e-mail-shaped text. The proptest generator now emits adjacent
   runs without spaces, up to three marks and marks together with links, whitespace at the inside edges of marks,
   words that start or end with punctuation or symbols, e-mail addresses, bare URLs, `a=b=c` and no-break spaces.
   That found five more failing shapes (merged `*****` runs, an inner `*` closing a `***` run, a text `_` closing a
   `_` italic, `!` before a mention, `=` pairs in text), all fixed and kept as cases in the new
   `convert::tests::markdown_delimiters_next_to_words_and_punctuation`. `markdown_roundtrip` and
   `markdown_print_idempotent` passed 30,000 cases each locally (`PROPTEST_CASES=30000`; the committed default stays
   128). The goldens are unchanged. The new timing case in `adversarial_markdown_bounded` (20,000 marked runs in one
   paragraph) also exposed a quadratic step in the lowering (one `retain` over the whole inline list per marked run,
   about 6 minutes in a debug build); it is one linear pass now (about 2 s).
4. **Low: the new-empty-item discard could delete another client's item** (`pages/DocPage.tsx`). Confirmed. Fixed
   (D20): only `location.state.created` counts; the time-based fallback is gone. W3-1 is now needed for items created
   from the top bar, the sidebar and the item menu.
5. **Low: contract text and code disagreed** (`quire-store/src/docs.rs`). `write_content` now takes
   `by: &WriteBy<'_>` as PLAN W4 "Produces" names it (it copies `by` into the owned `Author` its closures need). No
   change for `is_empty(conn: &Connection, …)`: a `&Transaction` derefs to it, W0b's callers compile unchanged, so
   it is the additive widening recorded in D2, not a break.
