## Deviations and choices

Where §7.6, §7.7, §13.2 or §14.1 give something exactly and W8 differs, the item says so; the rest are choices the
docs left open.

### Command line

- **D-W8-1. quire-cli is a library and a binary.** `src/lib.rs` holds the modules and `quire_cli::main()`; `main.rs`
  calls it. The tests need the clap tree (`args::Cli`, `args::try_parse_from`) and the coverage tables, which a
  binary-only crate cannot export.
- **D-W8-2. `doc put --json F` (deviation, forced).** clap cannot hold the global `--json` (no value) and a local
  `--json FILE`: their ids collide. The input flag is `--json-input FILE` (id `json_input`); before parsing, inside
  `doc put`, a `--json` that follows the ITEM and is followed by a value (`-` or a word without a leading `-`), and
  `--json=F`, become `--json-input`. So `quire doc put ID --json doc.json --if-match E` works as §7.6 writes it, and
  `quire --json doc put …` or a trailing `--json` is still the output mode. `help --json` lists `--json-input`.
  Request W7-1.
- **D-W8-3. More CLI error codes.** Besides `cli_usage`, `cli_config`, `network`, `timeout` and `tls`: `bad_response`
  (exit 1, an unparseable response) and `cli_io` (exit 1, a local file could not be written). An HTTP error whose body
  is not an envelope (a proxy page) gets `code: "http_error"` and the status's exit code. A 3xx is `cli_config` with
  `details.location`. An unreadable input file is exit 2 (`cli_usage`). Request W7-1.
- **D-W8-4. More warning codes, and `details`.** Besides `truncated`, `attach_skipped`, `api_version_older` and
  `token_file_permissions`: `discard_failed` (`item create --md` could not discard the new item; `details.id`),
  `item_created` (the title PATCH after a good PUT failed; `details.id`) and `server_unavailable` (`version` could not
  ask the server). Warnings may carry `details` (`attach_skipped`: `{path, reason}`; `truncated`: `{count,
  next_cursor}`).
- **D-W8-5. Output details §7.7 leaves open.** API bodies are printed byte for byte (plus a newline); CLI-built objects
  are pretty-printed. `auth logout` prints the ok object plus `profile` and `removed`; without `--revoke` its `status`
  and `request_id` are null. `doc get --format md --json` adds `warnings` (the codes of `Quire-Conversion-Warnings`).
  Without `--json`, `token create` prints the secret alone on stdout (so `> file` works). `help --json` prints
  `{name, version, api_version, global_flags, commands: [{name, path, about, arguments, flags, one_of?, commands?}],
  exit_codes}`; `quire help doc put --json` prints one subtree.
- **D-W8-6. `version`** never fails because of the server: with no URL, `server` is null; when the server cannot be
  asked, also a `server_unavailable` warning. `GET /config` is sent without a token.
- **D-W8-7. Input conveniences.** `doc put --json F` also takes a bare `{"type": "doc", …}` and wraps it in
  `{"schema_version": 1, "doc": …}`. `item create --md` reads the file before the POST (an unreadable file creates
  nothing), refuses `--kind board` (exit 2), and with `--title-h1` but no `--title` prints the item from
  `GET /items/{id}` (the POST's summary has no title yet). `--title` with `--title-h1`: the PATCH wins.
- **D-W8-8. References.** A `url_id` or URL costs one `GET /items/{url_id}` (or `/collections/{url_id}`) before every
  route except those two GETs, since §7.1 lets only them take a `url_id`. Positions and `--parent`/`--collection`
  resolve the same way.
- **D-W8-9. `search --titles`** refuses `--all`, `--cursor`, a `--limit` above 20 and the full-text filters (exit 2);
  the shared `--limit` flag otherwise allows 1–100.
- **D-W8-25. `auth logout --revoke` revokes the profile's own token.** It sends `DELETE /tokens/current` with the
  profile's token to the profile's URL, which is the token it then removes. When the resolved pair holds another token
  (`QUIRE_TOKEN`, `QUIRE_TOKEN_FILE`, `--token-file`, `--token-stdin`), the profile is resolved again on its own, as
  `--profile P` without token flags or `--url` would; that token is never revoked. No profile in play, or a profile
  without a URL and token, is exit 3 (`cli_config`) before any request, and nothing is removed.
- **D-W8-26. Human output escapes control characters.** Without `--json`, stdout text and every stderr line show C0,
  DEL and C1 characters (all but `\n`, and `\n` too inside a column or a tree line) as Rust escapes such as `\u{1b}`,
  so a server-supplied title or message cannot move the cursor or set colours. `--json` output is unchanged (an API
  body byte for byte), and so is raw content: `doc get` and `board get` without `--json`, and downloads.

### Configuration and transport

- **D-W8-10. The pair rule, refined.** A URL with the same origin as the profile's `url` (scheme, host and port, case
  and default port normalized) counts as the profile's URL, so its token pairs. With `--profile P`, `QUIRE_CA_FILE` and
  `QUIRE_ALLOW_HTTP` still apply (§7.6 ignores only `QUIRE_URL`, `QUIRE_TOKEN` and `QUIRE_TOKEN_FILE`). CA order:
  `--ca-file`, `QUIRE_CA_FILE`, the profile's `ca_file` (when the URL is the profile's). A `token_file` in the profile
  that is relative is relative to the profile file. `QUIRE_ALLOW_HTTP` accepts `1` and `true`. Without a config
  directory (no `HOME`, no `QUIRE_CONFIG`) there is simply no profile file.
- **D-W8-11. URLs** are `scheme://host[:port]` with an optional trailing `/`; a path, query or user info is exit 3
  (the server's public URL has no path either, D25). The `QUIRE_LISTEN` default follows the healthcheck rule (D26):
  an unspecified address becomes 127.0.0.1, a specific one is used as it is, and that URL may always be plain HTTP.
- **D-W8-12. `config show`** names the sources by their flag or variable: `url_source` is `--url`, `QUIRE_URL`,
  `profile` or `QUIRE_LISTEN`; `token_source` is `--token-stdin`, `--token-file`, `QUIRE_TOKEN`, `QUIRE_TOKEN_FILE` or
  `profile`. `profile` is the profile in play (`--profile`, `QUIRE_PROFILE` or `default_profile`) even when the URL
  came from elsewhere.
- **D-W8-13. `auth login`** writes `token` (from `--token-stdin`) or `token_file` (the absolute path of
  `--token-file`), keeps the profile's other keys and the other profiles, and sets `default_profile` only when the file
  has none. `token create --token-out F` and the profile both use a 0600 temporary file renamed into place;
  `token_file` in the JSON is F as given.
- **D-W8-14. No proxies.** The agent uses `proxy(None)`: `HTTPS_PROXY` and friends are ignored, so the token goes only
  to the configured origin (§7.6's "a token never travels to another URL").
- **D-W8-15. Retries.** `Retry-After` is read as seconds (an HTTP date falls back to 1 s / 3 s). HEAD counts as a read
  like GET. A DNS failure counts as "never left": std reports it as an uncategorized I/O error, so the agent's resolver
  maps it to `HostNotFound`, and a lookup that times out to a resolve timeout. "Not sent" is decided by the stage, not
  the error kind: every error of the resolver (`Lookup`) and of the connector chain (`ConnectStage` around ureq's
  `DefaultConnector`: TCP connect and the TLS handshake, which ureq completes with `complete_io` before it writes the
  request) is `details.sent: false`; with only a global timeout set, ureq names a connect or handshake timeout
  `Timeout::Global`, which `ConnectStage` turns into `Timeout::Connect`. Anything later is `details.sent: true`, a TLS
  error while the response is read included (it is never retried for a write). A pooled connection skips the
  connector, so a failure on it counts as sent.
- **D-W8-16. `api`.** Methods GET, POST, PUT, PATCH, DELETE and HEAD. It uses the 300 s transfer timeout (any route may
  be a download). `--out F` writes any response, JSON too. With no token configured it calls the route without one
  (public routes). The path guard also refuses control characters, spaces, `#`, and an encoded `/` or `\`; the header
  guard also checks the header name's syntax.
- **D-W8-17. Coverage allow-list (deviation).** `coverage::every_spec_operation_has_command_or_api_only_allowlist`
  allows, beyond §7.6's eight web-only operations, `GET /openapi.json` (the spec itself, through `quire api`) and
  `GET /items/{id}/board.inkboard` (the browser download; `board get` covers the same content). Request W7-2.
- **D-W8-24. Retrying a failed body read.** Every response the CLI reads into memory goes through
  `Client::send_text`: a GET or HEAD whose body stalls past the timeout or drops is sent again, within the same
  `--retries` budget as the attempts before the headers (`--retries 1` allows two attempts in all). A body over the
  1 GiB in-memory limit is not retried. Streamed bodies (`export`, `attachment get`, `board preview`, `doc get --out`,
  `board get --out`, `api … --out`, non-JSON `api` answers) are not retried once they started: part of them may
  already be on stdout or in the file. `api` reads a JSON answer into memory, so a JSON GET through `api` is retried.

### Harness

- **D-W8-18. Provisioned tokens expire in 2d (deviation from §14.1 step 3's 1d).** The server caps a created token at
  its creator's `expires_at` to the millisecond, so the scenarios' 1d tokens (`token create … --expires 1d`, PLAN
  scenario 10) would be refused (422) from 1d parents made a moment earlier. Scenario 10's second admin token
  (`quire admin create-token`) is 2d for the same reason. Request W7-3.
- **D-W8-19. Exit codes.** Usage is 2 (PLAN lists 0, 1, 3, 4; every script uses 2 for usage). `status` exits 3 when
  nothing is up; `down` always 0. `--ttl` is 1–15 minutes (R1).
- **D-W8-20. `lib.sh` additions.** `q`/`q_raw` also take `--token T` (an arbitrary token, still passed through the
  environment); `q_admin ARGS…` runs `quire --json admin …` inside the container (no host `quire-server`);
  `unknown_token` makes a well-formed unknown token (CRC32 from gzip's trailer); `val 'JQ'`; `ok NAME [DETAIL]`
  records a detail for a passing step (masked). TAP lines go to fd 3, so a check inside `$(…)` still prints. A failed
  check ends its scenario; the runner goes on with the next. A host CLI (`QUIRE_AGENT_CLI`) runs with every `QUIRE_*`
  variable of the caller unset and `QUIRE_CONFIG=e2e/agent/results/.no-config.toml` (never created), so neither the
  caller's profile file nor an exported `QUIRE_PROFILE`, `QUIRE_TOKEN_FILE`, `QUIRE_CA_FILE` or `QUIRE_ALLOW_HTTP`
  reaches a scenario; only `QUIRE_URL` and `QUIRE_TOKEN` are set.
- **D-W8-21. The report.** `e2e/agent/results/report.json` is `{image, revision, head, started, finished, passed,
  failed, failed_scenarios, steps: [{n, scenario, step, status, duration_ms}, plus command, rc, detail, out, err for a
  failure, and detail for a passing step that gives one]}`; `steps.jsonl` stays beside it. Both are masked. Scenario 10
  records `token create`'s stdout (the secret included) as a step detail and checks that the report holds `qpat_***`
  and not the secret, so the masking is exercised on a passing run.
- **D-W8-22. Scenario details.** 03 runs its own ETag, merge and `--title-h1` steps first and W4's goldens last (it
  fails while `fixtures/markdown/` has none); a `.warnings.json` may list codes or `{code, …}` objects. 04's fixture
  has one pen stroke, so page 0 has an SVG (an empty page answers 204). 05 searches `--titles Island` (the doc's title)
  rather than `quok`.
- **D-W8-23. AGENTS.md** shows `docker compose exec -T quire quire admin create-token … > agent.token` beside PLAN's
  `--token-out /tmp/agent.token`: that file lands in the container's tmpfs `/tmp`, and the distroless image has no
  shell to read it out.
