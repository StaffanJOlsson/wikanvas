## Deviations and choices

Additive changes to frozen contracts (R3):
- **D1. `AppState` has eight more public fields:** `clock`, `login_limiter`, `site`, `setup_code`, `last_used`,
  `single_flight`, `free_space` (the injectable probe of D33) and `dummy_hash`. Also added: `AppState::{now,
  with_assets, setup_message, check_free_space, dummy_hash}`, the `StartError::Inkboard` variant, and
  `state::{check_password_field, generate_setup_code, setup_code_matches}`. The limiter constructors take the
  `Clock` (`TokenLimiter::new(&config, clock)` and so on).
- **D2. `Config` has three more fields with no variable:** `fake_clock` (tests), `request_timeout` (30 s) and
  `upload_timeout` (120 s).
- **D3. `admin::NewOwner` has `seed: bool`.** `TestServer` has `owner_id`. `TestServer` creates the owner without the
  seed, so W8's tests still start with an empty workspace.

Choices where the docs are open:
- **D4. Login limiters.** Per IP: governor, 5 per minute, burst 5, shared with setup, counting every attempt.
  Per email: 10 failures in a sliding 15-minute window (`EmailFailures`), checked before the password is verified.
  governor cannot test a key without consuming it, and only failures may count, so this one is not governor.
- **D5. The limiter key without a peer address** (an in-process transport) is `0.0.0.0`: such requests fail closed
  and share one budget. `serve` and `TestServer` always have the peer.
- **D6. 429 reasons.** Login/setup per IP: `requests`. Login per email: `auth_failures`. Failed bearer per IP:
  `auth_failures`. Busy: `busy`. `Retry-After` is in whole seconds, at least 1.
- **D7. A malformed `qpat_` token counts against the per-IP failed-bearer limit too.** It still causes no lookup.
- **D8. The token byte budget.** `Content-Length` is counted at authentication, so an oversized declared body gets
  429 before the handler runs. Bytes without a `Content-Length`, or beyond it, are counted as the body is read. A body
  that goes over the budget is cut off, and the response becomes 429 `bytes`.
- **D9. Timeout.** tower-http's `TimeoutLayer` is replaced by a small middleware, so uploads and board PUTs
  (`PUT /api/v1/items/*/board`) get the 120 s body deadline of §8. Everything else gets 30 s. Both answer the 408
  envelope.
- **D10. Compression.** gzip at the fastest level, only for `application/json` and `text/markdown` bodies over 1 KiB
  without a `Content-Encoding`. That covers `/api` JSON, `openapi.json` and W4's Markdown GET. Static files and
  attachments are never re-encoded. Board-page SVG is not included (request W6-2).
- **D11. Headers on every response.** `X-Content-Type-Options: nosniff`. On `/api/` responses without their own
  policy, `Cache-Control: no-store`. HSTS on every response to an HTTPS request from the trusted proxy in `acme` mode,
  errors and static files included.
- **D12. Access log.** One span per request, `request{method, path, client_ip, token_id}`. A debug line logs the
  headers, with `Authorization`, `Cookie` and `Set-Cookie` shown as `Sensitive`. An info line logs the status and
  latency. `serve` writes ANSI colours only to a terminal, so `docker compose logs` stays plain text. An
  `Authorization` value that is not a Quire token is noted once per process at debug level (§8).
- **D13. Static serving.**
  - Root files other than `index.html` are identity only.
  - Requests for `*.br` / `*.gz` are 404. A non-GET/HEAD request to a static path is 405 (after the CSRF check).
  - The frame CSP and `X-Frame-Options: SAMEORIGIN` are on every file of the frame row except `icons.bin`.
  - The ETag is the first 16 bytes of the variant's sha256. Content types come from an extension table, so the
    rust-embed guess and the in-memory source agree.
- **D14. The manifest at startup.** A manifest that does not parse, or has a bad `build`, also refuses to start (as
  well as a `format_version` mismatch). The stub dist gives `inkboard: null`, but its files are still served under its
  build.
- **D15. Setup.**
  - A wrong code is 401 `invalid_credentials`.
  - The generated code uses 31 symbols (no 0/O/1/I/L), about 59 bits. The comparison ignores case and surrounding
    spaces, in constant time.
  - The order is: the IP limiter, then `already_setup`, then the code, then the fields (`email`, `name`,
    `workspace_name`, `password`).
  - Setup signs in with a browser-session (not persistent) cookie.
  - The setup link is logged by `serve` at startup while no owner exists.
- **D16. The seed.** "Writing in Quire" starts empty, because only one document fixture exists (request W4-1).
- **D17. Sessions.**
  - A due renewal, or a `last_seen_at` older than 5 minutes, is written on the request path (one small write).
  - `sessions.ip` follows the latest client address.
  - Login deletes the session the browser still presents (rotation).
  - Logout clears the cookie of the request's scheme with `Max-Age=0`.
- **D18. Validation fields.** Password change: a wrong `current` is 422 `current` (never 401), and a bad `new` is 422
  `new`. `DELETE /auth/sessions` without `others=true` is 422 `others`. `PATCH /auth/me`: an email change counts only
  when the address differs (ignoring case), and a taken email is 409 `conflict` with `details.field = "email"`.
  `PATCH /workspace`: the logo must be an existing PNG, JPEG, GIF, WebP or AVIF attachment (422
  `logo_attachment_id`).
- **D19. Uploads.**
  - The three form types are refused with 415 in the handler, after `Auth<S>`.
  - 413 is checked from `Content-Length`, and again while streaming.
  - An image over 100 MP is 422 with `field: "body"`.
  - An unknown `item_id` is 404.
  - The filename is also trimmed, and `.`/`..` become `file`.
  - Downloads stream the file in 256 KiB reads, with an ETag from the sha256.
- **D20. Export.**
  - The tar holds `manifest.json` (`format`, `format_version` 1, `created_at`, `server_version`, `api_version`,
    `schema_version`, `without`), `quire.db` and `files/aa/bb/<sha>`.
  - The single-flight guard lives in the response body, so it is released when the stream ends or the client goes
    away.
  - The cookie rule is checked after `Auth<S>`, so a request without credentials still gets 401.
  - **Security finding:** `PRAGMA optimize` (ANALYZE) writes `sqlite_stat4`, which keeps sample index keys. Those
    include token and session hashes. The copy therefore also deletes the `sqlite_stat1` / `sqlite_stat4` rows of
    `sessions`, `api_tokens`, `api_token_scopes` and `users` (D34 did not list them). `export::extracted_db_has_no_credentials_without_sidecars`
    caught it.
- **D21. Backups.**
  - `QUIRE_BACKUP_KEEP=0` turns the scheduled backup off. An on-demand backup then keeps only the new file.
  - Names taken within a minute get `-2`, `-3`, ….
  - `admin backup --out` refuses an existing file (422 → exit 10).
  - The GC also sweeps staging files in `tmp/` that are older than 24 h.
- **D22. Admin JSON shapes.**
  - `list-tokens`: `[ApiToken]`.
  - `revoke-token`: `{revoked}`.
  - `reset-password`: `{user, password, sessions_revoked, tokens_revoked}`.
  - `backup`: `{path, size}` (`BackupResult`).
  - `check`: `{ok, quick_check, foreign_key_violations, cycles, fts, missing_blobs}`. When something is wrong it exits
    1, with the report still on stdout.
  - `revoke-token` with an id that is not a UUID is 404 (exit 7).
- **D23. `authz::require`** keeps "the owner may do everything", and adds the obvious defaults for the other schema
  roles: `admin` everything, `member` read and write, `viewer` read only.
- **D24. `sniff`.** The ISO media brand decides before imagesize, which calls every `ftyp` HEIF. MP4 had come out
  as `image/heif`.
- **D25. `tokens::list`** selects every live token first, then the newest expired ones, up to 100, and returns them
  newest first. 100 newer expired tokens no longer hide a live one (W0b request 5).
- **D26. Test notes.**
  - `me_with_token_reports_auth_token` moved from `tokens.rs` to `auth.rs`, because the PLAN table lists it under
    `auth::`.
  - `authorization_redacted_in_logs` runs a real `quire-server serve` process and reads its output. A thread-local
    subscriber in the shared test binary missed events, because tracing's callsite interest is process-wide.
  - `malformed_token_401_without_lookup` proves "no lookup" by renaming `api_tokens`. A lookup would then answer 500.
  - `scopes_expanded_and_capped_by_caller`: PLAN says "a write token cannot mint admin: 422". But `POST /tokens` needs
    `admin` scope, so a write token gets 403 `insufficient_scope`. The 422 `scopes` cap can only be reached in the
    store (read parent, write child), and a token that asks for admin gets 403 `session_required` (W0b D23 order).
    The test covers all three (request W7-3).
