### Found by the review fixes, and by the gate

| Problem | Cause | Fix and test |
|---|---|---|
| **A server panic on a streamed board body for a gzip client** (found by smoke step 16 on its first run: the Welcome card's preview never loaded) | The first request for the seeded board's preview is rendered on demand and streamed under the body budget (`routes/boards.rs` `send`, a `futures::stream::unfold`). The compression layer gzips it for a client that accepts gzip, and its encoder polls the body once more after the end; `unfold` panics then ("Unfold must not be polled after it returned `Poll::Ready(None)`"), which kills the connection task. Every board body over 1 MiB (a large board GET) goes through the same stream. It had never been hit: on-demand previews were only fetched without gzip, and the smoke's boards are small | `4624614`: the board stream and the export's stream are fused. `boards::on_demand_preview_gzipped_for_a_gzip_client` (it panicked before the fix); smoke step 16 |

The test process's race, not the CLI's | `7629c25`: `run_json` and the passthrough test's run of its copy go through `spawn_output`, which retries only `ExecutableFileBusy`, for up to two seconds; any other error fails as before |

#### Decisions taken within the docs at the review (also in ARCHITECTURE §17.4)

- **Item links' DOM href** is `/item/<uuid>`, a new redirect route (§9.1), not the item's `/doc/<slug>-<url_id>`: the
  link mark holds only the id, a slug changes with every rename, and resolving it would need a query per link inside
  ProseMirror. The stored mark keeps `wikanvas://item/<uuid>` (§6.4 unchanged).
- **The link gesture** (implemented default, and an owner question below): follow on a click when read-only, on
  Ctrl/Cmd+click while editable; a plain click while editing places the caret.
- **Opening an empty document** holds the editor's own updates on the client; the server does not seed an empty
  paragraph (that would change `docs::is_empty`, the discard rule and every API writer).
- **The board card's missing preview** is requested on demand; no preview job is added to the seed or to duplicate.
- **New empty boards** are discarded like documents (§9.6.4 already says "every new item action"); the server decides
  emptiness.
- **The `--json` usage message** is clap's first paragraph on one line; no `details.missing` field was added (§7.7's
  error shape stays as it is).
