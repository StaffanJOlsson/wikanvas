## Deviations and choices

### Build pipeline (`scripts/inkboard.sh`)

- **D1. wasm-opt flags from trunk's source, not from `trunk build -v`.** §10.5 says to capture them once from a trunk
  run; reading trunk 0.22.1's `src/pipelines/rust/mod.rs` (`wasm_opt_build`) gives the same answer without another
  10-20 min release build. For Inkboard's `index.html` (`data-wasm-opt="s"`, no `data-reference-types`, no
  `data-wasm-opt-params`) trunk runs `wasm-opt --output=OUT -Os IN` and nothing else; wasm-bindgen gets
  `--target web --no-typescript`. Recorded in the script (`WASM_OPT_FLAGS`). binaryen 131 validates the output
  without feature flags.
- **D2. The warning baseline.** `check --record-baseline` (allowed only when `HEAD` = `base`) writes
  `patches/inkboard/check-baseline.txt`: 11 warnings, all clippy pedantic on the wasm target, in files the series
  does not touch (`live_web.rs`, `platform_web.rs`, `session_net_web.rs`, `watch_web.rs`) and in `inkboard-net`.
  Native has none (upstream CI runs clippy natively only). Warnings are compared as `<kind> <file>: <message>`,
  without line and column, so a patch that moves code adds nothing.
- **D3. Feature sets of `check`.** As §10.5, for `-p inkboard-app`: native default with `--all-targets` (so the
  tests compile too), wasm with `--target wasm32-unknown-unknown`. Which sets apply is read from the patched
  manifest's `[features]` (`embed`, `net`), not from the patch file names.
- **D4. `build --quick`** (not in §10.5): release code with `lto=false`, 16 codegen units and incremental (through
  `--config`, files untouched), no wasm-opt, brotli 5 / gzip 6. About 1.5 min instead of a full release build, for
  frame-test iteration only; the Dockerfile never passes it.
- **D5. `src` guards and staleness.** `src` refuses to discard uncommitted changes or unexported commits in
  `.cache/inkboard-src` (`src --force` does). `.git/quire-src-stamp` records the inputs (the submodule's file list
  with sizes and mtimes, and the patch contents) and the `HEAD` after `git am`; `build`, `check` and `size` rerun `src`
  only when the inputs changed, and `export` refreshes the stamp. The base commit has fixed dates and the tag `base`.
- **D6. The patchset id** is the `| Patchset | \`1\` …` row of the README's Base table, which `build` parses
  (exactly one row). `engine_version` = `0.2.0-beta.3+embed.quire.1`.
- **D7. `size`** builds `web-glow,embed` with and without `net`: with 0003 applied, "without patch 0003" is the
  `net` feature switched on, which compiles exactly what the unpatched dependency did.
- **D8. Small additions to the script:** `build` refuses a dist with wasm-bindgen JS snippets (it must stay flat) and
  a `web/inkboard-frame/inkboard.js` (it would shadow the engine); `export` refuses a commit message that contains
  the notice text; `export --upstream` checks its own output for notices.

### The series (§10.2)

- **D9. Patch subjects.** `format-patch` names come from the subjects, so they are `theme: sync egui theme`,
  `embed: js api`, `optional net` and `docs: embedding`. The author is `quire <quire@localhost>`.
- **D10. 0001** also adds a regression test, `theme::tests::a_system_theme_switch_keeps_the_applied_visuals`
  (it fails without the fix).
- **D11. 0002 against the §10.2 table:**
  - `host_load(&str)` stays, and `host_load_doc(Document)` does the resets: `mount` parses the board once, before
    eframe starts, so it can reject `load`. The resets also clear `paste_count` and set `last_key`, so a load is
    never reported as a change.
  - `host_snapshot`/`host_load*` are `#[cfg(all(target_arch = "wasm32", feature = "embed"))]`, and `HostMode` has
    `allow(dead_code)` outside that cfg (nothing builds one natively), so native builds get no new warning.
  - Added `host_guard()`, run every frame for a read-only host, as `session_guest` does for a read-only guest
    (tool Hand or Laser, no drag but panning, no editing). `setReadOnly(true)` commits the text being typed first.
  - The change key is `(revision, hash of the pending text)`, and the hash is 0 while nothing is pending, so starting
    to edit a label is not a change.
  - Hidden when hosted: also the separator after Language. "Import Mermaid…" and the exports stay.
  - `platform::init_page()` takes no context (it needs none). The paste listener ignores pastes while the board has
    no focus, also on the page of its own.
  - JS API details §10.3 leaves open: `setBoard(null)` shows a new empty board (inkboard.d.ts updated); unknown
    `theme` means `'board'`; `lang` other than `en`/`fr` means the browser's; an inert handle (destroyed, or the
    engine stopped) throws `{kind:'start'}` from `snapshot`/`setBoard` and returns 0 / false from
    `revision`/`isDirty`; `setActive(false)` asks for no frame, `setActive(true)` asks for one; `version` and
    `formatVersion` are plain properties of a frozen object.
- **D12. 0003 against the §10.2 table:** "Join a session…" is hidden by a compile-time condition (wasm without
  `net`), not by `join.factory.is_none()`: the native screenshot and visual tests run without a factory and would lose
  the entry. `check_relay_url` without `net` errs with a `NoNetwork` type instead of `()` (clippy pedantic
  `ignored_unit_patterns` fires at the `join_ui.rs` caller otherwise). `web-test` implies `net`.
- **D13. 0004** documents the API in English and French and adds `[Unreleased]` changelog entries (embed, net, the
  theme fix).

### Frame page and test

- **D14. `frame.js` choices:**
  - `connect` reads `manifest.json` next to the frame: the wasm's raw size is the `onProgress` total, `patchset` gives
    `engineVersion`, and `format_version` must equal the engine's (else `start`). Repeated `connect` calls share one
    attempt (the events are replaced); after a `download` failure the next `connect` retries.
  - `open` calls run one after the other. The first resolves once the engine has drawn its first frame, then sends
    `onReady(itemId)`; later ones call `setBoard`, `setReadOnly`, `setName` and `setTheme`, then send `onReady`. A
    failed `setBoard` reports the new itemId and keeps the previous board (and its itemId) in the engine.
  - `snapshot()` throws while no board is open. `lang` is never passed (the browser's language, as today).
  - Host keys: Mod is Cmd on macOS and Ctrl elsewhere, as in `app/hotkeys.ts`; Mod+K and Mod+. are stopped before
    the engine sees them; the first Esc still reaches the engine, a second within 500 ms calls `parent.focus()` and
    sends `onHostKey{key:'Escape'}`.
  - `pagehide` loses the WebGL context only when the page is not going into the back/forward cache.
- **D15. The frame test against the §14 row:**
  - **setActive:** the row counts `requestAnimationFrame` calls, but eframe 0.33's web runner requests an animation
    frame on every display frame and paints only when a repaint is due (measured: 121 calls and 0 paints in 2 s while
    inactive). The test counts WebGL draw calls instead, after checking that they do grow while active.
  - **Round trip:** compared without each page's `view`, which the engine refits to the canvas on open.
  - **Background page:** headless Chromium keeps reporting `visibilityState === 'visible'` for a page brought behind
    another, so that test records a skip, as §14 allows. A second test emulates the visibility (an init script
    overrides `document.visibilityState`) and checks the frame's own wait: a board opened while hidden mounts only
    once visible.
  - Extra checks: the PLAN two (`loaded == total`, title unchanged), Mod+K and double-Esc forwarding, no CSP
    violation under the frame CSP, the wasm served as br, `engineVersion` equal to the manifest's.
- **D16. `serve-static.mjs`** sends the §11 frame CSP and `X-Frame-Options: SAMEORIGIN` with HTML and answers
  `name.br` / `name.gz` (with `Content-Encoding` and `Vary`) when Accept-Encoding offers them, so the test runs the
  engine under production headers. Caching stays `no-store`.
- **D17. The fixture** is written by hand in the engine's canonical form (the round trip proves it); its name is
  "Frame test".
- **D18. Process:** I once ran `node --check e2e/serve-static.mjs` on the host (a syntax check, nothing built),
  against R1. Everything else ran through the wrappers.

1. `open()` resolves once the board is shown (the first one after the engine's first frame) and then sends
   `onReady(itemId)`; keep `BoardLoading` up until then. Call `snapshot()` only after an `open()` resolved: it throws
   while no board is open.
2. While a label is being typed, `isDirty()` stays true even right after `markSaved`; the snapshot already contains
   the text, and the end of the editing is reported as a change.

   (BoardPreview).
4. `onHostKey` sends `key` `'k'`, `'.'` or `'Escape'` with `mod`/`shift`/`alt`, ready for `runHostShortcut`.
5. The frame passes no `lang`: Inkboard's own menus follow the browser's language (English or French). If Quire
   wants English only, that is a new optional `OpenArgs` field (`bridge.ts` is W5's; ask).

## Follow-ups

- 0003 built cleanly on the first day, so it stays (PLAN order 7); dropping it is still a file delete. Its size gain
  is small (about 1.6 %, 245 KB raw / 76 KB br), because the `embed` build's `main` never installs the guest factory
  and the linker drops most of the network anyway; the real gains are that iroh and `ring` are not compiled (no C
  compiler for wasm) and that the embedded engine cannot open a network connection.
- The frame test needs `scripts/inkboard.sh build` (or `build --quick`) first; against the stub dist only its first
  test is meaningful. A full engine build plus the frame test take about 5 minutes of lock time.
- `.cache/inkboard-target` holds native and wasm debug artifacts (about 3 GB) besides the release build.
