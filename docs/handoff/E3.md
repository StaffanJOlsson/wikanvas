## Deviations (decided within the owner decisions and §18; for the merge stage to fold into §18 and §18.14)

- **E3-D1. What re-renders.** §18.5 says React renders only when the drawn set changes (ids, items, which is
  editing). The drawn cards also carry `label` (the snapshot shown while loading and struck through when missing) and
  `selected` (for "Double-click to edit"), so a label or selection change renders too. Neither changes during a pan,
  a zoom or a drag (the selection is fixed while dragging), and the embedLayer test checks that ten camera layouts
  render no card.
- **E3-D2. `chooseCards(…, overlaySize, …)`** keeps the parameter, but the controller passes `null`: the engine's
  `canvas` already lies inside the frame, and reading the overlay's size in every layout would force a style recalc.
- **E3-D3. Ending editing does not wait for the flush.** The engine is told (`setEmbedEditing(null)`), the frame
  focused (Esc) and the card back to static at once; the flush and `destroy` follow on one chain, which every later
  session (of any target) awaits before its `GET …/doc`. So "flushes the first before opening" holds for any second
  card, and the card never lingers in editing during a slow POST.
- **E3-D4. `['docJson', id]` holds `CachedDocJson {json: DocJson, etag}`**, not the bare `DocJson`, so the ETag the
  response came with is sent as `If-None-Match`. The editor's last JSON written at the end keeps the previous ETag
  (a 304 then means "nothing new on the server").
- **E3-D5. Opening a card whose target is not cached** (an undrawn card, below zoom 0.5 or beyond the cap): the host
  starts editing at once (focus, `setEmbedEditing`) and fetches the detail; a target that turns out trashed,
  archived, missing or not a document ends it silently and gives the frame focus back. A target whose detail query
  already failed is ignored, like a cached dead one.
- **E3-D6. The editing card's title input** has the classes `board-embed-card-title board-embed-title-input` and the
  accessible name "Page title" (the board's own top-bar title input is "Title"). It shows as soon as the target's
  detail is there, also while the session still opens (the body keeps the static viewer until then).
- **E3-D7. Header layout.** The header is exactly `HEADER` (40 world units) tall, `border-box` with the 1 px rule as
  its bottom border, 16 px side padding and the 18/26 title centred; 8 px of vertical padding (§18.5 review fix)
  would make it 43.
- **E3-D8. Out of the tab order.** A static card is `aria-hidden`, so its two pointer exceptions (the read-only
  title link and the Retry of the save badge) get `tabindex="-1"`; keyboard users reach the page through the sidebar.
- **E3-D9. A press below the text** of the editing body (outside ProseMirror's element) puts the caret at the end;
  percentage heights cannot make the editor fill a flex body reliably.
- **E3-D10. Code splitting.** `BoardFrameHost` is in the shell, so a static import of the cards put TipTap
  (≈ 900 kB) into `index.html`'s preloads. The cards (`EmbedCard`, `StaticViewer`, `QuireEditor`) are loaded
  dynamically once a board is shown, and the controller imports `DocSession` dynamically.
- **E3-D11. The picker.** Results are buttons whose accessible name is the title (`aria-label`); the path shows
  beside it. The first search (blank query) runs at once, later ones after 250 ms. The card is inserted in an effect
  after the dialog unmounted, so `frame.focus()` comes after the dialog gave focus back to its button.
- **E3-D12. The drag title** is read through a ref when the drag starts, so it is never older than a rename; the host
  still prefers the cached `ItemDetail` (§18.6 (c)).
- **E3-D13. Refetch on open.** "Refetched when the board opens" is done at the first layout after every `open()`: the
  host invalidates `['docJson', id]` and the cached `['item', id]` of that layout's `items`.
- **E3-D14. Additive contract changes (R3)**, all optional: `HostState.layer`; host exports `EmbedSink`,
  `setEmbedSink`, `currentEmbedLayout`, `lastEmbedItems`, `openInFrame`; `QuireEditorProps.variant/popupRoot/
  titleInput` and optional `pickBoard`/`newBoard`; `SlashContext.pickBoard?/newBoard?`, `SlashItem.needs`,
  `slashItemsFor`; `EditorSetup.variant/titleInput`, `viewerExtensions`; `SuggestPopup.portal`,
  `SelectionMenu/TableMenu.appendTo`; the docs.ts `docJson` exports; `FakeFrameOptions.embeds` and the fake's
  helpers. `BoardFrameContext.requestFullscreen` keeps its signature and now fullscreens the frame layer (D73).
- **E3-D15. A drop on the editing card** only happens for drags started outside this window: a drag of a sidebar row
  begins with a pointerdown in the parent, outside the card, which ends the editing first (§18.5 step 5), so that
  drop lands on the canvas. The overlay's capture listeners are there as specified.
