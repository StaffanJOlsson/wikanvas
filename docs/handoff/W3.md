## Deviations and choices

- **W3-D1. Sibling order** (the client sorts every group, `buildTree`): manual by `sort_key` (code-unit order), then
  `id`; title A–Z with `Intl.Collator('en', {sensitivity: 'base', numeric: true})`; updated and created newest first;
  ties by `sort_key`, then `id`. §9.6.2 names the orders but not the directions (request W1-1).
- **W3-D2. Drop details the docs leave open** (`tree/drop.ts`, `positions.ts`):
  - the "after" zone of an expanded parent means "before its first child";
  - outdent walks up one level per 16 px step while each node is the last child (§9.6.3 shows one level);
  - before/after send both neighbours, the moved row left out; "inside" and collection drops omit `position` (last);
  - a drop that changes nothing sends no request (no toast). That includes before/after the moved item itself: the
    first child dropped on the "after" zone of its own expanded parent keeps the indicator line but is a no-op;
  - dragging a collection over the items of an expanded collection reorders before/after by the half of its block.
- **W3-D3. Provisional sort keys.** An optimistic move gives the row a display-only key between its new neighbours
  (`applyMove.provisionalKey`); it is never sent, and the response replaces the row (D6 holds).
- **W3-D4. Toasts.** Drag-and-drop and Move… show "Moved to <parent> · Undo" (8 s); keyboard moves (Alt+Shift) show
  none, only errors. Trash, Archive and collection delete also get an Undo (restore / unarchive), which §9.6 does not
  ask for.
- **W3-D5. Keyboard extras.** Shift+F10 and the ContextMenu key open the row's ⋯ menu. Type-ahead: repeating one letter
  cycles; a prefix that matches nothing restarts with the last letter. Every single printable character types ahead,
  with Shift (capitals, Shift digits, punctuation) or AltGr (`getModifierState('AltGraph')`, which Windows reports as
  Ctrl+Alt); other Mod or Alt chords and whitespace do not. `?` never types ahead: it always reaches AppShell's
  shortcuts dialog, even from a focused row (§9.6.3 lists both).
- **W3-D6. The update check also compares `commit`** (version, commit or `inkboard.base`, §9.1 names two): dev images
  keep version 0.1.0 between builds. The baseline is the first `/config` the page loaded (`configBaseline()`).
- **W3-D7. Lazy chunk errors.** React Router 8.4.0 drops the rejection of a lazy `Component` on a route without a
  loader (the page silently renders nothing). `lazyPage()` therefore resolves a failed import to a component that throws
  it during render, so the route's `ErrorBoundary` (RouteError) runs the update check.
- **W3-D8. Additive contract changes (R3):** `useStar` variables gained optional `position` and `item`; new exports
  `modPressed` (hotkeys), `safeNext` (urls), `configBaseline`/`resetConfigBaseline` (config), `checkForUpdate`
  (`app/updateCheck`), `onBoardRowHover`/`boardRowHovered` (`state/hover`), `fullWidthOf` and `useFullWidthOf`
  (ItemMenu), `state/fullWidth` (`useFullWidthStore`, `setFullWidthSetting`, `fullWidthSetting`, `resetFullWidth`),
  `starReorderVars` (StarredSection), `typedChar` and the optional `TreeKey.altGraph` (treeKeyboard), and
  `components/sidebar/autoExpand` (`AUTO_EXPAND_MS`, still re-exported from CollectionsTree, `autoExpandKey`,
  `AutoExpandTimer`); the test probe of `test/sidebarHarness` gained `star`. `meKey` and `fetchMe` now live in
  `queries/auth.ts` and are re-exported from AuthGate. No frozen signature changed.
- **W3-D9. Full width.** `ItemDetail` has no `full_width` field, so ItemMenu's "Full width" (a `menuitemcheckbox`)
  keeps the toggled value in `state/fullWidth` (per item id, until the page reloads) and also writes it into the cached
  detail so pages re-render. A refetch of the detail (the PATCH invalidates `['item']`) no longer drops it.
  `fullWidthOf(item)` returns the detail's own `full_width` when the server sends one (request W1-2), else the session
  value, else false; `useFullWidthOf(item)` is the same as a hook. A failed PATCH rolls both back. Without W1-2 the
  setting does not survive a reload.
- **W3-D10. Token secret.** `createToken` is a plain function (`useCreateToken` wraps it with pending/error state), not
  a TanStack mutation, whose cache would keep the `CreatedToken`. The test checks the query cache, the mutation cache,
  the DOM and both storages after the dialog closes. Scopes are sent as the one chosen scope (`['write']`); the server
  expands them (§7.3).
- **W3-D11. ItemMenu and TopBar.** Duplicate, Move…, Archive and Delete are disabled for a trashed item. The split
  button's menu has Document, Board, Nested document and Nested board; Alt-click on "+ New doc" makes a child. TopBar
  and PageHeader start with a sidebar toggle while the sidebar is collapsed or a drawer.
- **W3-D12. Pages.** Search keeps its parameters in the URL (`q`, `collection`, `kind`, `updated=day|week|month|year`
  as the start of that local day, `archived=1`, `sort=updated`; typing is debounced 250 ms); Home keeps `?tab=updated`.
  Login defaults "Keep me signed in" on and sanitizes `next` (`safeNext`: only a path starting with one `/`, no
  backslash or control character, that parses to the same origin and not to `//…`; it returns the parsed path, query
  and hash, and `/login…` or `/setup…` give `/home`); it redirects to /setup when `/config` says
  setup is required, so it now fetches `/config` (the W0b router test asserted no fetch at all; it now asserts no
  `/auth/me`). Setup checks 12 bytes and the repeat on the client. Account with `?force=1` puts the password form first.
  Data's export is a plain `<a download>` of `/api/v1/export`.
- **W3-D13. AuthGate.** While an earlier error is being refetched it renders nothing; a 401 on a later `/auth/me`
  refetch opens the sign-in dialog instead of leaving the page; `afterSignIn` drops the cached `/auth/me` (otherwise
  the old 401 bounced a fresh sign-in back to /login).
- **W3-D14. Hit zones without the hitbox package.** The 25/50/25 and 50/50 zones are W3's pure functions, so they test
  without a browser; `@atlaskit/pragmatic-drag-and-drop-hitbox` stays declared but unused. pragmatic-dnd's element
  adapter and auto-scroll do the dragging; the drop handling is `useItemActions().drop` and
  `useCollectionActions().reorder`, which the sidebar tests call directly (happy-dom has no native drag events).
- **W3-D15. Test edits in W3-owned W0b tests:** `components/item/contract.test.tsx` (the new ItemMenu entries) and
  `app/router.test.tsx` (heading "API tokens", the `/login` and `/setup` fetch rule).
- **W3-D16. Collection icons:** the 48 names in `components/collection/icons.ts`, `rocket` first (§9.6.7).

## Review findings

All five findings of the independent review hold; each was checked against the code and the docs and fixed inside
W3's Owns table. None was rejected, and none needs another workstream.

1. **Fixed (medium): a drop could target the dragged item itself** (`components/tree/drop.ts`, `positions.ts`). The
   first child dropped on the "after" zone of its own expanded parent resolved to "before itself" and sent
   `before_id` = the moved item, moved it last on screen and toasted "Moved to …". `dropToMove` now returns null for
   before/after the moved item itself; `resolveItemDrop` keeps the indicator line there (the item's current place, as
   for other no-op drops). Tests: `tree/hitZones` (drag A's first child, and an only child, onto the parent's "after"
   zone: no move), `tree/positions` (before/after self is null), `sidebar/optimisticMove` (no request, no toast, rows
   unchanged). W3-D2 updated.
2. **Fixed (low): "Full width" snapped back after the PATCH's refetch** (`components/item/ItemMenu.tsx`). The value now
   lives in `state/fullWidth` (per item id) as well as the cached detail; `fullWidthOf` prefers a server
   `full_width`, then the session value. Test: `item/fullWidth` (checked and "full" after the PATCH and the refetch of
   a detail without the field; off again on the second toggle; rollback with an error toast on a failed PATCH). This
   test fails against the old code. W3-D9 and the W4 request updated; W1-2 still stands for persistence across reloads.
3. **Fixed (low): type-ahead ignored Shift characters** (`components/sidebar/treeKeyboard.ts`). Type-ahead now runs
   before the plain-key check and takes any single printable character with Shift, or with AltGr (CollectionsTree
   passes `getModifierState('AltGraph')`); `?` is kept for the shortcuts dialog (recorded in W3-D5). Tests:
   `tree/keyboard` (Shift+G, Shift+B on the rendered tree; `?` not consumed; digits, `(`, AltGr `@`, and refused
   Mod/Alt chords on the pure mapping).
4. **Fixed (low): `safeNext` let `/\t/evil.example` through** (`lib/urls.ts`). It now refuses every C0 control
   character and DEL as well as the backslash, parses the rest against a fixed origin, requires that origin and a path
   that does not start with `//` (dot segments such as `/a/..//host`), and returns the parsed path, query and hash.
   Tests: `lib/urls` (tab, newline, CR, NUL, dot-segment cases; ordinary targets unchanged; `/login#x`, `/setup`).
5. **Fixed (low): untested W3 behaviours.** New tests:
   - `sidebar/autoExpand` (fake timers): 700 ms of "inside" on a collapsed row (item or collection) expands it,
     not 1 ms earlier; same-row updates do not restart the wait; another zone, another row or the drop cancels it. The
     monitor's logic moved into `components/sidebar/autoExpand.ts` (`autoExpandKey`, `AutoExpandTimer`), which
     CollectionsTree now uses; the timer is also cancelled on unmount.
   - `sidebar/starReorder`: `starReorderVars` (the STARRED drop, now exported from StarredSection) maps to both
     neighbours; `useStar` with a position reorders the section at once, sends `PUT /items/{id}/star {position}`, keeps
     the confirmed order, and rolls back on an error.
   - `app/appShell` (BoardFrameHost mocked, so W6's real host does not change it): `flushPending()` runs on a pathname
     change and not on a query change; below 1024 px the sidebar is a drawer (inert until opened; the backdrop and a
     route change close it); at 1024 px and wider Mod+. collapses it; Mod+S flushes and is prevented; `?` opens the
     shortcuts dialog outside text fields only; an `auth-lost` event opens the sign-in dialog over the page.
   - `overlays/moveDialog`: the item and its descendants are not offered (also for a top-level item with a subtree),
     the current parent changes nothing, the filter narrows, and Move sends the new parent (across collections) with
     no position.
   - `overlays/collectionDialog`: the 12 colours equal §9.6.1 in order, 48 distinct icons plus the letter tile
     (`rocket` first), create posts the choice and opens the collection, edit is prefilled and patches.
